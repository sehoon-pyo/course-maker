## ADR-1. 도구는 clone으로 받아 업데이트하고, 강의는 별도 저장소를 `default-course` template으로 만든다

**상태**: 확정, 일부 구현 전 ([261007_003] ADR-2의 "강의는 강의별 별도 저장소"를 구체화함. template 저장소는 아직 만들지 않음)

**맥락**
강의를 도구와 같은 저장소에 두는 fork 방식을 검토했으나 채택하지 않았다. 사용자가 도구를 가져간 뒤에는 그 강사의 스타일대로 계속 가므로 원본 이력을 이어 갈 이유가 없고, 도구는 계속 개선되므로 업데이트는 받아야 한다.

**결정**
- **fork는 쓰지 않는다.**
- **도구(`course-maker`)는 사용자가 clone으로 받고 `git pull`로 업데이트한다.**
- 강의는 도구 저장소와 별도의 git 저장소이고, 도구 저장소의 `.gitignore`는 `courses/*`를 무시하고 예제(`sample`, `sample2`)만 추적하는 지금 규칙을 유지한다.
- **강의의 초깃값은 별도의 `default-course` template 저장소**로 만든다. 사용자는 `courses/` 폴더 안에서 이 template으로 자기 강의 저장소를 만들어 clone한다.
- **template은 복사한 시점에 고정된다.** 그 뒤 template이 바뀌어도 받지 않는다.
- 지금의 `courses/default-course/`는 임시용이다(`.gitignore` 때문에 도구 저장소가 추적하지 않는다).
- 공개 범위: 지금은 public(누구든 볼 수 있고 가져가도 된다)이고, 필요한 시점에 private로 바꿔 collaborator에게만 공유한다. `README.md`의 사용 조건("승인한 사람만 사용")과 "비공개" 안내는 뺐다.
- 폰트는 무료 폰트만 쓴다.

**결과**
- 정하지 않았다: `default-course` template 저장소를 만드는 시점과 이름.
- `README.md` 4번에 도구 업데이트 방법(`git pull`)을 한 줄로 적었다.

## ADR-2. 마스터는 강의가 가지고, 요소와 폰트는 도구에 둔다

**상태**: 확정, 구현됨 ([261007_003] ADR-3의 "도구가 제공하는 마스터는 `src/masters/{id}/`에 둔다"와 "없으면 `default`"를 도구가 마스터를 제공하지 않는 것으로 바꿈. [261007_004] ADR-10의 `default` 마스터 위치를 옮김)

**결정**
- 도구(`src/masters/`)는 마스터를 제공하지 않는다. 기본 마스터를 `courses/sample/masters/default/`와 `courses/default-course/masters/default/`로 옮겼다. 마스터의 assets(로고)는 마스터와 함께 간다.
- 마스터 id는 `default` 그대로이고 기본 id(`DEFAULT_MASTER_ID`)도 `default`이다. 폴더가 `masters/` 아래에 있으므로 이름이 혼동되지 않는다.
- 마스터 id 조회 순서(① 강의 `masters/` → ② `src/masters/`)는 코드를 바꾸지 않았다. `src/masters/`에 마스터를 두면 모든 강의가 쓰는 마스터로 읽힌다.
- 요소(`src/elements/`), 마스터 로딩 코드, 폰트(`assets/fonts`)는 도구에 둔다. 강의마다 복사하면 코드와 용량이 중복된다. 강의 전용 요소는 지금처럼 강의의 `elements/`에 둔다.
- 새 강의는 `default-course` template(ADR-1)에서 시작하고, 그 안에 마스터가 들어 있다.
- 강의에 마스터가 없으면 "마스터를 찾을 수 없습니다" 오류에 마스터 폴더의 위치(`courses/{강의}/masters/{id}/index.tsx`)를 확인하라는 안내를 붙인다(구현함). 해결 방법(복사 등)은 안내하지 않는다.

**결과**
- `sample`은 마스터 복사본을 갖는다. 같은 마스터가 `sample`과 `default-course`에 두 벌 있다.
- 2026-10-08 확인: `npm run typecheck`와 `npm run build` 통과, 사용자가 `sample`과 `default-course`의 미리보기가 잘 열리는 것을 확인했다.

## ADR-3. 도구 API 버전 관리 체계는 만들지 않고, 깨지는 변경은 ADR에 적는다

**상태**: 확정 ([261007_003] ADR-2 "결과"의 "API 버전 관리 방법은 정하지 않았다"와 [261007_004] ADR-12의 "도구 API 버전 관리는 정하지 않는다"를 정함)

**결정**
- 버전 번호나 호환 선언은 두지 않는다.
- 도구가 바뀌어 기존 강의가 깨지면 그 ADR에 **"강의에 필요한 수정"**을 적는다(`CLAUDE.md` 문서 규칙에 추가함). 도구를 업데이트한 사람은 이 설명을 보고 강의를 고친다.

**결과**
- 도구는 업데이트되고 강의는 복사한 시점에 고정되므로(ADR-1) 도구 변경이 강의를 깨뜨릴 수 있다. 이미 [261008_001] ADR-1이 기존 강의의 `meta.ts`에 `chapters`, `sections`를 추가해야 읽힌다고 적은 사례가 있다.
