## ADR-1. 마스터는 `defineMaster` 객체이고, 이번 구현 범위를 정한다

**상태**: 확정, 구현됨 ([261007_003] ADR-3에서 미뤄 둔 `defineMaster`의 형태를 확정함. `extendMaster`는 [261008_003] ADR-11로 폐기함)

**맥락**
마스터 구조는 [261007_003] ADR-3에서 정했지만 마스터 안의 모양(layout, 슬롯, 배경)과 API는 layout을 정할 때 확정하기로 미뤄 두었다.

**결정**
- `src/masters/{id}/index.tsx`(도구 제공)와 `courses/{강의}/masters/{id}/index.tsx`(강의 전용)는 **`defineMaster({...})`가 만든 객체**를 내보낸다. React 컴포넌트가 아니다.
- 마스터 안에 `background`와 `layouts`가 있다. layout, 슬롯, 배경 층, 상속이 모두 데이터로 선언된다.
- 이번 구현에 포함한다.
  - `CourseMeta.master`(선택) 추가
  - `CourseMeta`에 section의 표시 이름(예: `SECTION`, `UNIT`, `MODULE`)을 강의마다 정하는 선택 필드 추가. 필드 이름은 `sectionLabel`로 하고 구현할 때 확정한다. 지정하지 않으면 `SECTION`이다. 목차, 미리보기의 사이드바, 상단 바(breadcrumb)가 이 값을 쓴다. 표시 형식(예: `SECTION 1`)은 구현할 때 정한다.
  - 마스터 등록과 조회(조회 순서와 오류는 [261007_003] ADR-3을 따른다)
  - `default` 마스터
  - layout, 자유 배치 요소(ADR-7), `Chip`과 `PromptBox`(ADR-8)

**결과**
- 데이터로 선언된 값은 PPTX 변환과 이후의 도구 수정에 유리하다.
- `extendMaster`는 이 ADR에서 정하지 않는다([261007_003] ADR-3의 결정을 유지).

## ADR-2. layout과 슬롯

**상태**: 확정, 구현됨

**결정**
- 마스터는 layout을 가진다. `default` 마스터는 **대제목, 목차, 컨텐츠(제목 및 내용), 제목만 있는 컨텐츠** 4개로 시작한다. 챕터 구분 layout은 이번에 넣지 않는다.
- layout은 **슬라이드 크기(1920×1080px)의 컨테이너**이고, 슬롯은 그 안에 **절대 위치**로 놓는다. **좌표 단위는 px**이다.
- 슬롯은 `{ id, type, x, y, w, h }`로 선언한다. `type`은 `title`, `subtitle`, `body`, `free` 등이다.
- 같은 모양이 반복되는 줄(목차의 항목)은 **`list` 슬롯 하나**로 선언한다: `{ id, type: "list", x, y, w, h, rows, pitch, columns }`. `columns`는 열마다의 `x, w`와 글자 속성이고, 줄 간격은 균일한 `pitch`로 한다. 슬라이드에서는 목차 요소(예: `Toc`)가 항목 배열로 채운다. PPTX export에서는 줄 수만큼 열별 플레이스홀더로 풀어서 내보내, 받은 사람이 줄마다 편집할 수 있게 한다.
- **목차 요소(예: `Toc`)는 현재 슬라이드가 속한 chapter의 section 목록으로 항목을 자동으로 채운다.** 항목의 이름은 section `meta.ts`의 `title`, 번호는 section 순서이고, 앞에 `sectionLabel`을 쓸 수 있다. section이 `list` 슬롯의 `rows`보다 많으면 넘치는 항목은 표시하지 않고 경고한다. 항목을 직접 지정하는 방식은 두지 않는다(자동으로만 채운다).
- 슬라이드의 요소는 **종류로 자동 매핑**한다(`Title` → `title`, `Bullets`/`Paragraph` → `body` 또는 `free`). 모호할 때만 `slot` prop으로 지정한다.
- 슬롯 안 내용이 넘쳐도 그대로 두고 경고만 한다. 한 슬롯에 요소가 여럿이면 세로로 쌓고, 간격은 마스터의 토큰으로 정한다.

**결과**
- 슬라이드 크기가 모든 출력에서 고정이고 글자 크기와 여백도 px라 비율 좌표의 이점이 없다. 미리보기의 확대 축소는 슬라이드 전체에 `transform: scale`을 적용하므로 px 좌표와 문제가 없다.
- PPTX 추출(`getClientRects()`)은 배율 1인 export 모드에서 해야 한다.
- 기존 PPTX는 77장 중 67장이 "제목만 있는 컨텐츠"에 본문을 직접 놓아 만들었다. 그래서 `free` 슬롯을 일급으로 둔다.
- layout의 이름(id)은 구현할 때 정한다.

## ADR-3. 쌓는 단계와 순서

**상태**: 확정, 구현됨

**결정**
- 쌓는 단계는 **background(맨 아래) < layout < element(맨 위)**로 고정이다. 한 단계의 요소는 다른 단계를 넘지 못한다.
- 각 단계 컨테이너가 자기 쌓임 맥락(stacking context)을 가진다(`position: absolute; inset: 0; isolation: isolate`와 단계마다 고정된 `z-index`).
- 단계에 들어가는 것: master 전체에 반영되는 로고와 장식은 `background`, 특정 layout에만 반영되는 것(로고, 구분선, 슬롯 테두리 등)은 `layout`, 슬라이드의 요소는 `element`이다.
- **단계 안의 쌓는 순서는 배열 순서**이다. `z-index` 숫자는 소스에 쓰지 않고, 렌더링할 때 배열에서 만든다(`index × 100`). 슬라이드의 요소는 작성 순서대로 쌓는다.
- 모든 층, 슬롯, 요소에는 안정적인 `id`를 둔다.

**결과**
- PPTX export에서는 단계 순서 → 단계 안의 순서로 도형 순서를 정한다.
- 숫자 `z-index`는 간격 소진과 재번호 문제가 있어, 이후 화면 편집을 붙일 때 이동 연산이 어렵다. 배열 순서와 `id`는 "어느 것 위로 옮긴다"는 연산 하나로 표현된다. 화면 편집은 이 ADR에서 정하지 않는다.

## ADR-4. 배경은 층의 구성이고, 상속은 `id`로 대체한다

**상태**: 확정, 구현됨 ([261007_002] ADR-1의 "layout은 master의 background를 상속"을 구체화함)

**결정**
- `background`는 색 하나가 아니라 **아래에서 위로 쌓이는 층(layer)의 배열**이다. 색, 이미지, 도형이 함께 올 수 있다.
- 층은 `{ id, type: "color" | "image" | "shape" | "text", ... }`이다.
  - `image`: `{ src, x, y, w, h }`(px)
  - `shape`: `{ path, viewBox, fill, shadow, x, y, w, h }`. PPTX의 자유형 값을 그대로 옮길 수 있다.
  - `text`: `{ value, x, y, w, h, size, color, align }`. layout에 고정된 문구(목차의 "CONTENTS", "목차" 등)를 위한 층이며, 슬라이드의 `Text` 요소와 같은 글자 속성을 쓴다.
  - 이미지 파일은 마스터 폴더의 `assets/`에 두고 상대 경로로 가져온다.
- layout마다 `background`를 다르게 지정할 수 있고, **지정하지 않으면 master의 `background`를 그대로 상속**한다. 지정하면 master의 층 배열 위에 다음 규칙으로 적용한다.
  - **같은 `id`**의 층은 그 자리에서 대체한다(순서는 master 것을 따른다).
  - master에 없는 `id`의 층은 새 층이며 master의 층 위에 자기 선언 순서대로 쌓는다.
  - `{ id: "logo", remove: true }`로 master의 층을 뺄 수 있다. 존재하지 않는 `id`를 `remove`하면 오류로 알린다.
- 이 상속과 대체는 `background`에만 적용한다(layout은 부모 layout이 없다).

**결과**
- 층 사이에 새 층을 끼우는 앵커(`above` 등)는 만들지 않는다. 필요해지면 추가하며, 앵커가 없을 때의 기본 동작이 그대로라 기존 소스가 깨지지 않는다.

## ADR-5. 슬라이드 디자인은 마스터가 가진다

**상태**: 확정, 구현됨

**맥락**
테마 토큰, 배경, 요소 모양이 `src/styles.css`에 있고, 배경은 미리보기 영역(`.slide-preview-area-slide`)이 칠한다. 미리보기 영역은 export에 없다.

**결정**
- 슬라이드 디자인(테마 토큰, 배경, 요소 모양)은 `styles.css`가 아니라 **마스터**가 가진다.
- 마스터의 값은 CSS 변수로 노출하고 `[data-master]`로 범위를 한정한다. 요소는 변수만 읽는다.
- 도구에 남는 것: `@font-face`, 미리보기 UI, 슬라이드의 구조(크기 100%).
- 지금 미리보기 영역이 칠하는 배경은 마스터의 `background` 층으로 옮긴다.
- **Tailwind 같은 utility class 방식은 채택하지 않는다.** 요소마다 클래스로 디자인을 제어하면 디자인이 마스터 한곳에서 정의된다는 구조가 깨진다.

**결과**
- `default` 마스터의 값이 지금의 `styles.css` 값과 다르므로(ADR-9) 기존 샘플의 모습이 바뀐다.

## ADR-6. 마스터 적용 방식

**상태**: 확정, 구현됨

**결정**
- 마스터는 슬라이드를 그리는 **공통 경로**에서 적용한다. 미리보기 전용이 아니다. export에도 같은 마스터가 적용되어야 한다.
- 공용 `MasterFrame`(`src/masters/MasterFrame.tsx`)이 해석된 마스터를 prop으로 받아 context로 내려 주고, 슬라이드 크기의 컨테이너(`.slide`, `data-master`)를 그린다. 미리보기와 export가 같은 `MasterFrame`을 쓴다.
- 마스터는 `resolveMaster(course.master)`로 찾는다(`course.master ?? "default"`). 조회 순서와 오류는 [261007_003] ADR-3을 따른다.
- `Slide`는 `layout` prop(선택)으로 layout을 고르고 background, layout, element 세 단계를 각각 그린다. `layout`이 마스터에 없으면 사용 가능한 layout 목록과 함께 오류로 알린다. 마스터 밖에서 `Slide`를 그리면 오류로 알린다.
- `Title` 같은 요소는 context에서 자기 종류의 슬롯을 찾아 슬롯의 `x, y, w, h`로 절대 위치에 놓는다.
- `MasterFrame`은 마스터와 함께 슬라이드가 속한 chapter의 정보(section 목록)도 context로 내려 준다. 목차 요소가 이를 읽는다.
- 슬라이드 파일은 바꾸지 않는다. `layout`을 생략하면 기본 layout(컨텐츠 계열)으로 그린다.

**결과**
- layout이 범위에 들어왔으므로 `Slide`가 현재 마스터를 읽어야 하고, 그래서 context를 쓴다.

## ADR-7. 슬라이드의 자유 배치 요소

**상태**: 확정, 구현됨

**맥락**
기존 PPTX는 77장 중 67장이 본문을 슬라이드에 직접 놓아 만들었다. 슬롯 안에 요소가 세로로 쌓이는 방식만으로는 이런 슬라이드를 만들 수 없다.

**결정**
- **`Text`, `Shape`, `Image` 요소**를 추가한다. 이들은 선택적인 `at={{ x, y, w, h }}`(슬라이드 기준 px)을 받는다. `at`이 없으면 슬롯에 자동으로 들어가고, 있으면 절대 위치에 놓는다.
- 문구는 슬라이드 맨 위 `text` 객체에 모으는 규칙을 유지하고, 좌표는 JSX의 `at`에 선언한다. 좌표는 선언이므로 "슬라이드에 로직을 넣지 않는다"와 충돌하지 않는다.
- 이번에 하지 않는 것: `Group`(그룹 기준 상대 좌표), `Row`/`Column` 같은 자동 배치, 표.
- **`Shape`의 속성**(단위 px): `kind`(`rect`, `roundRect`, `ellipse`, `rightArrow`, `triangle`, `line`, 자유형 `path`), `radius`(둥근 모서리), `fill`(색, 없음, 투명도), `line`(색, 굵기, 실선/점선), `rotate`, `shadow`(바깥 그림자), `text`(도형 안의 글자).
- **`Text`의 속성**: `size`, `color`, `align`(왼쪽/가운데/오른쪽), `anchor`(위/가운데/아래), `bold`, 바탕 `fill`, 줄 간격. 폰트는 R/B 두 가지뿐이라 `bold`로만 고른다.
- **색은 직접 값(`#FF0000`)과 마스터의 토큰 이름(예: `primary`)을 둘 다 받는다.** 표시용 색은 강의가 직접 값을 쓰고, 일반 색은 토큰을 쓴다.

**결과**
- `Image`의 속성과 슬라이드의 이미지 파일 위치는 정하지 않았다.

## ADR-8. `Chip`과 `PromptBox`는 요소로 추가하고, 모양은 마스터가 정한다

**상태**: 확정, 구현됨 (요소 자체는 구현됨. PPTX export에서 도형, 선, 그림, 글상자의 그룹으로 풀어서 내보내는 부분은 export를 만들 때 한다). 칩의 아이콘 칸과 프롬프트 박스의 `icon`, 강의 전용 칩은 [`[261008_002]_adr.md`](./[261008_002]_adr.md) ADR-4. "결과"에서 정하지 않았던 요소의 디자인 선언 방식은 [261008_003] ADR-12, 안쪽 배치와 여러 줄 처리는 [261008_003] ADR-15로 정함)

**결정**
- **`Chip`**: 둥근 사각형 안에 아이콘과 글자를 넣는 요소이다. 폭은 글자에 맞춰 자동으로 계산한다. 아이콘은 이미지 경로를 받는 일반적인 속성이다. 모양은 마스터가 정한다. 도구는 아이콘 이미지를 제공하지 않는다.
- **`PromptBox`**: 도구 요소이다. `<PromptBox at={{ x, y, w, h }} value={text.prompt} />`. 바탕, 테두리, 구분선, 글자 색은 슬라이드가 아니라 마스터의 디자인이 정하고, 안쪽 배치는 박스 크기를 기준으로 계산한다. 문구는 다른 요소처럼 `text` 객체에 둔다. 기본값은 기존 PPTX의 현재 값(바탕 `#0C0C0C`, 테두리 `#D77757` 3px, 구분선 흰색 3px, 글자 `#FFC000`)이다. 아이콘은 선택 속성이며 도구는 아이콘 이미지를 제공하지 않는다. 색과 아이콘을 바꾼 변형은 강의의 `elements/`(ADR-9)에 만든다.
- 두 요소는 PPTX export에서 도형, 선, 그림, 글상자의 그룹으로 풀어서 내보내, 받은 사람이 편집할 수 있게 한다.
- 위 두 가지 외의 도형(화살표, 번호 원, 강조 테두리, 도장, 배너, 점선 박스 등)은 새 도구 요소를 만들지 않고 `Shape`/`Text`의 속성으로 표현한다.

**결과**
- 요소가 마스터의 디자인을 어떻게 선언하는지(`defineMaster`의 `elements` 등), 안쪽 배치 규칙, 여러 줄 처리는 정하지 않았다.

## ADR-9. 강의 전용 요소 `courses/{강의}/elements/`

**상태**: 확정, 구현됨 (chapter 바로 아래의 슬라이드(`head`, `tail`)는 `../../elements`로 가져온다: [`[261008_002]_adr.md`](./[261008_002]_adr.md) ADR-2. 아이콘이 정해진 칩과 도장 예는 ADR-4, 5)

**결정**
- 특정 강의에서만 쓰는 요소는 **그 강의의 `courses/{강의}/elements/`**에 둔다. `masters/`와 같이 도구 저장소를 건드리지 않고 강의 저장소 안에서 확장한다.
- 강의 전용 요소는 도구의 `Chip`, `Shape`, `Text`를 조합해서 만든다. 아이콘 이미지와 표시용 색(강의 고유의 빨강, 하늘색, 노랑 등)은 그 강의가 가진다.
- **슬라이드는 상대 경로로 가져온다.** 슬라이드는 항상 `courses/{강의}/ch.N_이름/sec.N_이름/sl.N_이름/index.tsx`에 있어 강의 폴더까지의 깊이가 고정이므로, 모든 슬라이드에서 `import { ... } from "../../../elements"`로 같다.
- 강의의 `elements/index.ts`는 도구의 요소를 다시 내보내고(`export * from "@/elements"`) 자기 요소를 같은 이름으로 내보내면 **강의 것이 우선**한다. 그러면 슬라이드는 한 줄로 도구 요소와 강의 요소를 함께 가져온다. `elements/`가 없는 강의는 지금처럼 `@/elements`를 쓴다.
- 예: Agent 강의의 아이콘별 칩(`claude`, `terminal`, `file`, `vscode`), 색과 아이콘을 바꾼 `PromptBox` 변형, 단계 번호, 강조 테두리, 설명 캡션, 도장, 점선 박스, 각주.

**결과**
- 도구 저장소에는 특정 강의의 아이콘 이미지가 들어가지 않는다.
- 같은 이름의 명시적 내보내기가 `export *`보다 우선하는 ES 모듈의 동작에 기대는 규칙이다. 이 프로젝트에서 시험해 보지는 않았다.
- README와 CLAUDE.md의 구조도에 이 폴더를 반영하는 것은 구현할 때 함께 한다.

## ADR-10. `default` 마스터의 값

**상태**: 확정, 구현됨 (`default` 마스터 파일의 위치는 [261008_003] ADR-21로 강의의 `masters/default/`로 옮김)

**결정**
- `default` 마스터는 기존 PPTX(`2_Agent_View_기반_병렬_개발_r8.pptx`)의 마스터와 layout 4개(대제목, 목차, 컨텐츠, 제목만 있는 컨텐츠)를 따른다. 좌표와 크기는 1920×1080px로 환산한 값(1px = 6350 EMU = 0.5pt)을 쓴다.
- 색은 PPTX의 값을 가져온다. 주색 `#164194`, 진한 주색 `#204273`, 연한 회색 `#E7E6E6`. 마스터 자체의 배경은 흰색이고 장식은 없다.
- layout의 장식 도형과 **로고**를 모두 가져온다(대제목의 양쪽 도형과 로고, 컨텐츠의 위쪽 띠와 삼각 탭, 목차의 패널과 띠). 로고는 대제목 layout에만 넣는다.
- 로고 파일은 `src/masters/default/assets/logo.svg`, `logo.png`에 둔다.

**결과**
- 현재 `styles.css`의 주색(`#1f4e79`)이 바뀌므로 기존 샘플 17장의 모습이 바뀐다. 샘플은 바뀐 모습으로 확인한다.
- 장식 도형의 바깥 그림자는 PPTX export에서 어떻게 처리할지 정하지 않았다([261007_001] ADR-4는 복잡한 그림자를 이미지로 처리하기로 했다).
- 목차의 고정 문구("CONTENTS", "목차")는 `text` 층(ADR-4)으로, 항목 10줄은 `list` 슬롯(ADR-2)으로 표현한다. 기존 PPTX의 줄 간격(73~80px)은 균일한 `pitch`로 단순화하므로 줄 위치가 최대 약 8px 달라진다.
- 로고는 특정 브랜드의 이미지이다.

## ADR-11. PPTX export는 진짜 PPTX 슬라이드 마스터로 만든다

**상태**: 확정, 구현 전 (PPTX export를 만들 때 구현한다. 마스터, layout, 슬롯, 층은 export가 읽을 수 있는 데이터로 이미 선언되어 있다)

**결정**
- 마스터는 PPTX의 슬라이드 마스터로, layout은 슬라이드 레이아웃으로, 슬롯은 플레이스홀더로, 배경 층과 장식은 마스터와 layout의 도형으로 내보낸다. 받은 사람이 PowerPoint에서 편집하기 쉽게 하기 위해서다.
- 슬롯의 `type`은 PPTX 플레이스홀더 종류(title, subTitle, body 등)에 대응한다. `free` 슬롯은 플레이스홀더로 만들지 않을 수 있다.
- 이전의 "진짜 마스터로 올릴지, 슬라이드마다 복제할지" 미결은 **올린다**로 정한다.
- **슬라이드 본문 텍스트는 문단마다 텍스트박스 하나로, 자동 줄바꿈을 켜서 내보낸다.** [261007_001] ADR-4의 "줄마다 텍스트박스, 자동 줄바꿈 끔"을 이 부분에서 대체한다. 받은 사람이 문단 단위로 편집할 수 있게 하기 위해서다.

**결과**
- 줄바꿈은 PowerPoint가 다시 하므로 HTML과 달라질 수 있다. 얼마나 달라지는지는 PPTX export를 만들 때 PowerPoint와 비교해 확인하고, 문제가 크면 다시 정한다.
- 문장 안의 `badge()`, `code()`(알약, 코드 배경)는 PowerPoint 글 흐름 안에 넣을 수 없다. 인라인 요소가 있는 문단의 내보내기 방식은 정하지 않았다.
- 자유형 도형과 바깥 그림자를 PPTX의 도형 속성으로 쓸 수 있는지 확인하지 못했다.

## ADR-12. 이번에 하지 않는 것

**상태**: 확정 (날짜, 바닥글, 번호 슬롯은 [261008_003] ADR-16, 표와 `Group`, 자동 배치, 앵커는 [261008_003] ADR-17, 도구 API 버전 관리는 [261008_003] ADR-22으로 정함)

**결정**
- 미리보기의 **마스터 선택 드롭다운**은 넣지 않는다. 마스터가 `default` 하나뿐이다. 둘 이상이 되면 넣는다.
- **날짜, 바닥글, 슬라이드 번호 슬롯**은 넣지 않는다. 나중에 한다.
- `Group`, 자동 배치(`Row`/`Column`), 표, 층 사이에 끼우는 앵커는 만들지 않는다. 필요해지면 추가한다.
- **화면에서 편집하고 임시 JSON을 거쳐 소스를 바꾸는 기능**은 만들지 않는다. 이 기능을 만들게 되면 [261007_003] ADR-1("화면에서 직접 고쳐 TSX에 저장하는 기능은 만들지 않는다")을 대체하는 새 ADR을 남긴다. 이번 구현에서는 모든 항목에 `id`를 두는 것(ADR-3)만 반영한다.
- **도구 API 버전 관리**는 정하지 않는다. 강의가 늘어 문제가 보일 때 정한다.

## 구현 결과 (2026-10-08)

위 결정을 모두 구현하고 확인했다. 구현 과정과 확인 방법은 [`docs/plan.md`](../plan.md)에 있다. 구현에서 확정한 것과 결정과 달라진 것은 다음과 같다.

- **layout id와 기본값(ADR-2, 6)**: `title`, `content`, `title-only`, `toc`. `<Slide>`에 layout을 생략하면 `content`이다.
- **요소와 슬롯의 대응(ADR-2)**: `Title` → `title`, `Paragraph` → `body`(없으면 `subtitle`, `free`), `Bullets` → `body`(없으면 `free`), `Toc` → `list`. 맞는 슬롯이 없으면 경고하고 그리지 않는다. `slot` 속성으로 슬롯 id를 직접 지정할 수 있다.
- **`title` layout의 `subtitle` 슬롯(ADR-10)**: 기존 PPTX에 없는 슬롯이다. 샘플의 대제목 슬라이드가 부제를 쓰므로 추가했다.
- **`Shape`와 `PromptBox`는 `at`이 필수이다(ADR-7, 8)**: 크기가 없으면 의미가 없기 때문이다. `Text`, `Image`, `Chip`은 선택이고 `w`, `h`도 생략할 수 있다.
- **색 표기(ADR-7)**: 토큰 이름은 `--color-{이름}`으로 해석한다(`primary` → `--color-primary`). 직접 값(`#FF0000`, `rgba(...)`)도 쓸 수 있다.
- **필수 토큰(ADR-5)**: 도구의 기본 요소가 읽는 토큰 10개를 마스터가 반드시 정해야 하고, 빠지면 오류를 낸다. `--chip-*`, `--promptbox-*`는 해당 요소를 쓸 때만 필요하다.
- **chapter 정보(ADR-6)**: `MasterFrame`이 마스터와 함께 chapter의 `sectionLabel`, section 목록을 context로 내려 `Toc`가 읽는다.
- **그림자와 목록 슬롯(ADR-2, 4)**: 그림자 `blur`는 PPTX의 번짐 반경과 같은 뜻이고 렌더링에서 CSS `drop-shadow`의 표준편차(반경의 절반)로 바꾼다. `ListColumn`에 `fill`을 더했다(목차의 번호 칸).
- **강의 전용 요소의 우선순위(ADR-9)**: `export *`와 같은 이름의 명시적 내보내기는 TypeScript 7과 Vite 8에서 기대대로 동작했다. 슬라이드가 `../../../elements`에서 가져오면 강의의 요소, `@/elements`에서 가져오면 도구의 요소이다.
- **`extendMaster`는 구현하지 않았다(ADR-1).** CSS를 어떻게 합칠지가 정해지지 않았다.

**남은 것**: PPTX, HTML, PDF export(ADR-11, 숨김 슬라이드 제외 포함), 본문 텍스트의 PPTX 내보내기에서 인라인 `badge()`/`code()`가 있는 문단의 처리, 자유형 도형과 그림자의 PPTX 속성 사용 가능 여부, `Image`의 속성 확장, `extendMaster`, `Group`, 자동 배치, 표, 날짜/바닥글/슬라이드 번호, 도구 API 버전 관리.
