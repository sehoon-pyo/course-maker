## ADR-1. 구조 용어와 계층

**상태**: 확정

**맥락**
PPTX나 React, DOM에서 쓰는 용어와 우리 구조의 용어가 헷갈리면 안 된다.

**결정**
- 계층은 `course → chapter → section → slide → element`이다.
  - `course`: 하나의 전체 강의 (최상단 카테고리)
  - `chapter`: 실제 파일로 배포하는 단위
  - `section`: 수업 주제 단위. **PowerPoint의 구역(Section)과 같은 개념**이다.
  - `slide`: 슬라이드 한 장
  - `element`: 슬라이드의 구성요소(제목, 불릿, 그림, 표, 뱃지 등). **`group`으로 여러 element를 묶을 수 있다.**
- `slide-master`는 **PowerPoint의 슬라이드 마스터와 같은 개념**이다.
  - `slide-master` 안에 `background`와 `layout`이 들어 있다.
  - `layout`마다 `background`를 가진다. 기본은 master의 background를 **상속**하고, 필요할 때 layout에서 지정한다.
- **`component`와 `block`은 구조 용어로 쓰지 않는다.** (`component`는 React component와 혼동되고, 네 가지 종류를 통칭하는 상위 용어는 두지 않기로 함)
- **PPTX 고유 개념은 `pptx` 접두사, DOM 고유 개념은 `dom` 접두사**를 필요할 때 붙여 구분한다(예: `pptx layout`, `pptx master`, `dom element`). 접두사가 없으면 우리 구조의 용어로 읽는다.

**결과**
- 용어 정의는 [`docs/glossary.md`](../glossary.md)에 모아 둔다.
- `layout`의 종류와 PPT 슬라이드 레이아웃과의 관계는 이 ADR에서 정하지 않는다.

## ADR-2. 폴더 구조와 meta

**상태**: 확정 (slide 폴더 이름 규칙 `sl.N_{이름}`은 이후 확정됨, [`[261007_003]` 노트](../notes/[261007_003]_note.md) 참조. chapter와 section의 순서를 폴더 이름의 번호로 정하는 부분은 [`[261008_001]_adr.md`](./[261008_001]_adr.md) ADR-1로 대체됨)

**맥락**
계층을 파일 시스템으로 옮겨야 한다. 이전 ADR([261007_001] ADR-2)의 `decks/<이름>/deck.ts`, `slides/sNN-*.tsx` 구조는 계층이 정해지기 전의 것이다.

**결정**
```
courses/{강의명}/
  meta.ts
  ch.N_{chapter명}/
    meta.ts
    sec.N_{section명}/
      meta.ts                 section은 폴더이면서 meta
      sl.N_{이름}/            slide 폴더
        index.tsx             슬라이드 한 장 (슬라이드당 tsx 1파일 규칙 유지)
```
- course, chapter, section 폴더에는 각각 `meta.ts`를 둔다(`title` 등).
- slide는 **폴더별로 관리**하고, **section `meta.ts`의 `slides` 배열에도 포함**한다. 슬라이드 순서의 기준은 이 배열이다.
- chapter와 section의 순서는 폴더 이름의 번호(`N`)로 정한다.
- 문구는 슬라이드 파일 맨 위 `text` 객체에 둔다(이전 ADR-2 유지).

**결과**
- 이전 ADR-2의 파일 구성(`deck.ts`, `slides/`)은 이 결정으로 대체된다.
- slide 폴더 이름은 `sl.N_{이름}` 형식으로 확정한다(`ch.N_`, `sec.N_`과 같은 규칙). 슬라이드 순서는 폴더 이름의 번호가 아니라 section `meta.ts`의 `slides` 배열이 정한다.

## ADR-3. 개발 스택과 출력 단위

**상태**: 확정

**결정**
- **Vite + React + TypeScript**를 쓴다. 미리보기는 React 앱으로 한다.
- 최종 HTML은 **단일 HTML 파일로 export**한다. **`chapter` 하나가 배포 파일 하나(= 단일 HTML 하나)**이다.
- 지금 범위는 **미리보기 창 수준**까지이다. 단일 HTML export, PPTX/PDF export는 이후에 한다.
- 시각 비교 테스트(HTML ↔ PPTX)는 PPTX export를 만들 때 시행한다.

**결과**
- 미리보기 앱이 같은 코드로 개발 중 미리보기, Playwright 추출 대상, 최종 HTML 빌드를 겸한다(이전 ADR-4 파이프라인과 같은 방향).
- 단일 HTML은 `vite-plugin-singlefile` 같은 방식으로 만들 예정이며, 정확한 옵션은 구현할 때 확인한다.
- TypeScript 7에서는 `baseUrl`이 제거되어 `tsconfig`의 `paths`만 사용한다.

## ADR-4. 폰트는 R, B 두 가지만 사용

**상태**: 확정 (이전 ADR-5를 일부 대체)

**결정**
- NanumSquare의 **R(Regular)과 B(Bold)만** 사용한다. L(Light)과 EB(ExtraBold)는 쓰지 않고, 파일도 삭제했다.
- 폰트 파일은 `assets/fonts/`에 둔다. 라이선스는 프리(무료)이다.
- HTML에서는 `@font-face`로 R을 400, B를 700에 연결해 가짜 굵게(faux bold)를 쓰지 않는다.
- 굵기는 역할(테마 토큰)이 정하고, 텍스트 변수에는 문장 중간 강조만 `bold()`로 표시한다(이전 ADR-5 유지). 제목과 강조는 B, 본문은 R로 매핑한다.

**결과**
- 이전 ADR-5의 L/R/B/EB 4종 사용과 `heading: NanumSquareEB`, `caption: NanumSquareL` 예시는 폐기한다.
- 폰트가 2종이라 단일 HTML 용량이 줄어든다.

## ADR-5. 편집 주체와 AI 연동 방식

**상태**: 확정 ("서비스 형태"와 "agent 연동은 나중에" 부분은 [`[261007_003]_adr.md`](./[261007_003]_adr.md) ADR-1로 대체됨)

**결정**
- TSX를 고치는 주체는 **개발자**이다. 다만 이해하기 쉽게 작성한다(문구 분리, 이름이 분명한 컴포넌트와 헬퍼, 슬라이드에 로직을 넣지 않음).
- AI 연동은 **지금은 Claude Code 같은 도구를 켜 두고 TSX 수정을 시키는 로컬 방식**으로 한다. 미리보기는 React로 한다.
- 서비스 형태이지만 TSX는 아직 로컬에서 수정하며, **agent 연동은 나중에** 한다.

**결과**
- AI가 만든 TSX를 서버에서 실행하는 보안 문제는 agent 연동 단계에서 다시 다룬다.
