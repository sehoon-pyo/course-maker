## ADR-1. `extendMaster`는 없는 개념이다

**상태**: 확정 (코드는 바꾸지 않음. [261007_003] ADR-3의 "마스터는 `extendMaster(...)`로 다른 마스터를 확장할 수 있다"를 대체함. [261007_004] ADR-1과 ADR-12의 "남은 것"에 있던 `extendMaster`도 같은 이유로 폐기함)

**결정**
- 마스터끼리의 상속(확장)은 두지 않는다. slide master라는 개념만 남긴다.
- 마스터는 지금처럼 course 단위로 하나를 고른다. 강의별 차이는 마스터 파일을 따로 만들어 둔다.

**결과**
- `extendMaster`는 코드에 없었으므로 구현을 걷어낼 것은 없다. `CLAUDE.md`에는 반영했다.

## ADR-2. 요소의 디자인은 마스터의 `tokens`(CSS 변수)로만 선언한다

**상태**: 확정, 구현됨 ([261007_004] ADR-8 "결과"에서 정하지 않았던, 요소가 마스터의 디자인을 어떻게 선언하는지를 해결함)

**결정**
- `defineMaster`에 `elements` 같은 항목은 두지 않는다.
- 요소의 CSS는 변수만 읽고, 값은 마스터의 `tokens`가 정한다(`Chip`은 `--chip-*`, `PromptBox`는 `--promptbox-*`).
- 필수 토큰 10개(`REQUIRED_TOKENS`)는 늘리지 않는다. `--chip-*`, `--promptbox-*`는 해당 요소를 쓸 때만 필요하다.
- 마스터가 이 변수를 정하지 않으면 도구가 채우는 기본값은 없다.

**결과**
- `styles.css`는 이 변수를 `var(--chip-height)`처럼 대체값 없이 읽고 `:root`에도 정의하지 않는다(2026-10-08 코드 확인). 변수가 없으면 그 속성이 적용되지 않아 속성의 초기값으로 그려진다.

## ADR-3. `Image`의 속성은 현재 구현을 확정한다

**상태**: 확정, 구현됨 ([261007_004] ADR-7이 `Image`의 속성을 적지 않은 것을 채움)

**결정**
- 속성: `src`(필수, 강의 폴더의 이미지를 import한 주소), `alt`(선택, 기본 빈 문자열), `at`(선택. 없으면 슬롯, 있으면 절대 위치), `fit`(`contain`, `cover`, `fill`. 기본 `contain`이며 `at`에 `w`, `h`를 둘 다 줬을 때만 의미가 있음).
- 이미지 파일은 강의의 `assets/`에 둔다.
- 그 밖의 속성(`rotate`, 모서리 둥글림, 투명도, 그림자 등)은 필요할 때 추가한다.

**결과**
- PPTX export에서 `fit`(특히 `cover`의 잘림)을 옮기는 방식은 export 때 정한다.

## ADR-4. 슬롯의 넘침은 자르지 않고 경고하며, 경고는 상단 바에 모은다

**상태**: 확정, 일부 구현됨 (콘솔 경고와 `--slot-gap`은 구현됨. 상단 바 신호등과 `PromptBox`의 넘침 표시는 구현 전)

**결정**
- 슬롯 안 내용이 넘쳐도 자동으로 줄이거나 자르지 않는다. 슬롯 박스 밖으로 그대로 그리고 경고만 한다. 목차의 `list` 슬롯은 예외로 `rows`를 넘는 항목을 표시하지 않고 경고한다.
- 한 슬롯에 요소가 여러 개일 때의 간격은 슬롯 단위의 토큰 `--slot-gap` 하나로 정한다. 요소별 간격은 필요할 때 추가한다.
- **콘솔에 나오는 경고 전체**(슬롯 넘침, `list` 슬롯 넘침, 마스터 오류, `meta.ts`와 폴더 불일치 등)를 미리보기 상단 바에 모은다. 오류가 있으면 빨간 신호등이 켜지고, 눌러서 내용을 볼 수 있다.
- `PromptBox`는 지금 `overflow: hidden`으로 잘린다. 이것도 "그려서 경고"하는 방식으로 바꾼다.

**결과**
- 넘침이 PPTX에서 어떻게 보이는지는 export 때 확인한다.

## ADR-5. 여러 줄은 인라인 헬퍼 `br()`로 쓰고, `PromptBox`의 안쪽 배치는 현재 구조를 유지한다

**상태**: 확정, 구현 전 (`br()`). 안쪽 배치는 구현됨 ([261007_004] ADR-8 "결과"의 "안쪽 배치 규칙, 여러 줄 처리는 정하지 않았다"를 해결함)

**결정**
- 줄바꿈은 인라인 헬퍼 `br()`로 넣는다(``t`첫째 줄${br()}둘째 줄` ``). 문자열의 `\n`과 CSS `white-space: pre-line`은 쓰지 않는다.
- 이유: 줄바꿈이 CSS가 아니라 문장 데이터에 있어 HTML과 PPTX(`a:br`)의 결과가 어긋날 여지가 적고, 소스를 여러 줄로 써도 의도치 않게 줄이 바뀌지 않으며, `badge()` 같은 헬퍼로 서식을 쓰는 규칙과 맞는다.
- `br()`은 `PromptBox`만이 아니라 `Sentence`를 받는 모든 요소(`Paragraph`, `Bullets` 등)에서 쓸 수 있는 인라인 서식이다.
- `PromptBox`의 안쪽 배치는 현재 구조를 확정한다. 머리(아이콘, 있을 때만), 구분선, 글 영역이 세로로 쌓이고 값은 `--promptbox-*` 토큰으로 정한다. 새 규칙은 만들지 않는다.

**결과**
- 인라인 조각 타입을 어떻게 더할지는 `Inlines`를 읽고 구현 때 정한다.

## ADR-6. 슬라이드 번호 슬롯만 남기고, 날짜와 바닥글은 만들지 않는다

**상태**: 확정, 구현 전 ([261007_004] ADR-12의 "날짜, 바닥글, 슬라이드 번호 슬롯은 넣지 않는다. 나중에 한다"를 날짜와 바닥글은 만들지 않고 번호 슬롯만 남기는 것으로 좁힘. [261008_002] ADR-1에서 쪽번호 layout(번호 슬롯)을 만들 때 추가한다고 한 슬라이드 위 페이지 번호를 구체화함)

**결정**
- 날짜와 바닥글 슬롯은 만들지 않는다.
- 번호 슬롯은 layout에 포함한다. 표시 형식은 `n / N`이고 기준은 [261008_002] ADR-1이다(chapter 안에서 1부터, 숨김 슬라이드는 번호가 없고 `N`은 숨김을 뺀 수).
- 슬라이드에서 번호를 빼는 방법은 슬라이드 속성 `<Slide number={false}>`이다. 기본은 넣는 것이다.
- 번호 슬롯은 `content`, `title-only` layout에 포함하고 `title`, `toc`에는 두지 않는다.
- 숨김 슬라이드 위에서는 번호 슬롯에 "숨김"이라고 표시한다.
- 슬롯 모양: 기존 PPTX의 위치(`x1356 y1001 w432 h58`), 24px, 오른쪽 정렬, 세로 가운데, 색은 토큰 `muted`(`--color-muted`)이다. 적당히 정한 값이다.

**결과**
- 기존 PPTX는 컨텐츠 layout에만 번호 슬롯이 있었다는 기록이 있고, 나머지 layout은 확인하지 못했다. `title-only`에 포함하는 것은 이 결정으로 정했다.
- PPTX export에서 번호를 내보내는 방식은 export 때 정한다.
- 구현할 때 `README.md`와 `CLAUDE.md`의 "날짜/바닥글/슬라이드 번호는 아직 없다"를 "슬라이드 번호"로 줄이고 `docs/github.md`의 마일스톤 `날짜, 바닥글, 번호`를 `슬라이드 번호`로 바꾼다.

## ADR-7. 표만 로드맵에 남기고, 나머지는 지금 만들지 않는다

**상태**: 확정 ([261007_004] ADR-12에서 만들지 않기로 한 `Group`, 자동 배치, 표, 층 사이에 끼우는 앵커를 표만 마일스톤에 올리고 나머지는 삭제하는 것으로 정리함)

**결정**
- **표**는 마일스톤 `표 요소`에 둔다. HTML `table`과 PPTX `a:tbl`이 구조가 직접 대응하고 `colspan`, `rowspan`도 `gridSpan`, `rowSpan`에 대응한다([261007_001] 노트).
- **`group`, 자동 배치(`Row`/`Column`), 층의 앵커(`above` 등)**는 지금 필요하지 않아 노트와 문서에서 지운다. 필요한 사례가 나오면 새 항목으로 올린다.
- 목차 layout의 번호 칸과 제목 칸 색 `#6C93C6`은 쓰지 않는다. 용도를 확인하지 못했다. 확인되면 다시 연다.
- **화면에서 고쳐 TSX에 저장하는 기능**은 지금 만들지 않고 나중에 마일스톤으로 올린다. 만들 때 [261007_003] ADR-1을 대체하는 새 ADR을 먼저 쓴다. 마일스톤은 이 기능을 구현하기 직전에 추가한다.

**결과**
- 확인하지 못함: 기존 PPTX의 표 사용 빈도.
- 마일스톤 이름은 `슬라이드 요소 확장`에서 `표 요소`로 바꾸었다.

## ADR-8. `Stamp`는 도구 요소이다

**상태**: 확정, 구현됨 ([261008_002] ADR-5의 `Stamp`가 강의 전용이라는 서술을 대체함)

**결정**
- `Stamp`는 `src/elements/free.tsx`의 도구 요소이다(`Shape`를 조합한 요소). 강의의 `elements/index.ts`가 `export * from "@/elements"`로 받으므로 슬라이드의 import는 바뀌지 않는다.
- 색의 기본값(`#00B0F0`, 글로우 값)은 요소 안에 두고 마스터 `tokens`로 올리지 않는다. 슬라이드에서는 `color` 속성으로 바꿀 수 있다.

**결과**
- 마스터 tokens로 색을 정하는 규칙과는 어긋나지만, 쓰임이 한정되어 토큰을 마스터마다 정해야 하는 부담이 더 크다고 판단했다.

## ADR-9. 미리보기 상단 바에서 숨김 슬라이드의 표시 여부를 정한다

**상태**: 확정, 구현 전 ([261008_001] ADR-4의 숨김 슬라이드 동작에 표시 여부를 고르는 기능을 더함)

**결정**
- 상단 바에 토글 스위치를 두어 숨김 슬라이드를 보일지 정한다.
- 기본은 켜짐(보임)이다. 끄면 사이드바와 이동(`<`, `>`)에서 숨김 슬라이드를 건너뛴다.

**결과**
- 정하지 않았다: 끈 상태에서 하단 `n / N` 표기.
