## ADR-1. 사용 방식: 로컬 사용, 동적 수정은 파일 수정

**상태**: 확정 ([261007_002] ADR-5의 "서비스 형태"와 "agent 연동은 나중에" 부분을 대체)

**결정**
- **서비스로 배포하지 않는다.** 사용자는 **레포지토리를 내려받아 로컬에서** 사용한다.
- AI(Claude Code 등)가 로컬 저장소의 TSX를 직접 고치는 방식이 기본 사용 방식이다.
- **"동적 수정"은 파일 수정을 뜻한다.** 파일을 고치면 미리보기에 바로 반영되는 방식(Vite HMR)으로 충분하며, 화면에서 직접 고쳐 TSX에 저장하는 기능은 만들지 않는다.
- 슬라이드의 `text` 객체는 단순한 값(문자열, 배열, `badge()` 같은 헬퍼 호출)으로만 두고 로직을 섞지 않는다.

**결과**
- AI가 만든 TSX를 서버에서 실행하는 보안 문제, 웹 서버, 인증, 호스팅, 다중 사용자는 고려하지 않는다.

## ADR-2. 강의는 강의별 별도 저장소로 관리

**상태**: 확정

**결정**
- `courses/{강의}` 폴더마다 자기 `.git`을 가진 **별도 저장소**로 관리한다. `course` = 하나의 전체 강의 = 하나의 저장소.
- 도구 저장소의 `.gitignore`는 `courses/*`를 무시하고 예제만 추적한다(`!courses/sample/`, `!courses/sample2/`).
- 도구 저장소를 `git pull`로 업데이트해도 강의 파일과 섞이지 않고, 강의 저장소는 비공개로 둘 수 있다.

**결과**
- 강의 저장소의 슬라이드가 도구의 API(`@/elements` 등)에 의존하므로 도구가 바뀌면 강의가 깨질 수 있다. API 버전 관리 방법은 정하지 않았다.
- 대안으로 검토했으나 채택하지 않은 것: git submodule, 저장소 밖 폴더 지정(`COURSES_DIR`).

## ADR-3. 슬라이드 마스터 구조

**상태**: 확정 (구현은 layout을 정할 때 함께 한다)

**결정**
- **마스터는 course 단위로 고른다.** `courses/{강의}/meta.ts`의 `master` 필드(선택 사항)로 마스터 id를 지정하고, 없으면 `default`를 쓴다. chapter, section, slide 단위로 마스터를 바꾸지 않는다.
- 도구가 제공하는 마스터는 `src/masters/{id}/index.tsx`에 둔다. 폴더 이름이 마스터 id이고 `import.meta.glob`으로 자동 등록한다. `_`로 시작하는 폴더(`_shared`)는 등록하지 않고 공용 부품을 둔다.
- **강의 전용 마스터를 지원한다.** `courses/{강의}/masters/{id}/index.tsx`.
- 마스터 id 조회 순서: **① `courses/{강의}/masters/{id}` → ② `src/masters/{id}`** → 둘 다 없으면 사용 가능한 마스터 목록과 함께 오류. 같은 id가 양쪽에 있으면 강의 전용이 우선한다.
- 마스터는 `extendMaster(...)`로 다른 마스터를 확장할 수 있다.

**결과**
- 강의 하나는 마스터 하나만 쓰므로 chapter 하나가 되는 단일 HTML, PPTX, PDF에도 마스터가 하나만 들어간다.
- 마스터와 layout은 아직 코드로 만들지 않았다. `defineMaster`, `extendMaster` 등의 API는 layout의 모양과 함께 확정한다.

## ADR-4. 미리보기 창 구성

**상태**: 확정 (구현됨)

**결정**
- **사이드바**는 접고 펼 수 있고(상단 바의 ☰ 버튼), 상태는 `localStorage`에 저장하되 저장소를 못 쓰는 환경에서도 동작한다.
- 사이드바는 **선택된 chapter의 목차**(section → slide)를 보여 준다. 다른 chapter의 목차는 chapter 콤보박스로 바꾼다.
- **상단 네비게이션 바**에는 사이드바 토글, 현재 위치, 오른쪽의 항목 영역을 둔다. 오른쪽 영역에 **강의 선택 콤보박스**와 **chapter 선택 콤보박스**를 둔다.
  - 강의를 고르면 그 강의의 첫 슬라이드로, chapter를 고르면 그 chapter의 첫 슬라이드로 이동한다.
  - chapter 콤보박스에는 선택된 강의의 chapter만 나온다.
- 현재 위치는 **`chapter / section / slide` 순서**로 표시한다(강의 이름은 콤보박스에 있어 제외).
- 샘플 강의로 `courses/sample`(chapter 2개, slide 11장)과 `courses/sample2`(chapter 2개, slide 6장)를 도구와 함께 둔다.

**결과**
- 이전/다음 버튼, 방향키, `n / 전체` 표시의 기준(강의 단위인지 chapter 단위인지)은 아직 정하지 않았다. 현재는 강의 단위이다.

## ADR-5. 슬라이드 크기와 슬라이드 미리보기 영역 용어

**상태**: 확정 (구현됨)

**맥락**
"스테이지"라는 말이 고정 크기(1920×1080)와 미리보기에서 창에 맞춰 축소해 보여 주는 영역 두 가지를 같이 가리켜 혼동되었다.

**결정**
- **고정 크기는 별도 용어 없이 "슬라이드 크기"**라고 부른다. 1920×1080px(16:9)이며 HTML, PPTX, PDF 모든 출력에서 같다.
- **미리보기 창 안에서 슬라이드를 창 크기에 맞춰 비율 유지로 축소해 보여 주는 영역은 "슬라이드 미리보기 영역"(`slide-preview-area`)**이라고 부른다. 슬라이드 자체가 아니라 슬라이드를 보여 주는 영역이며, 미리보기에서만 있고 export에는 없다.
- **"미리보기 창"은 사이드바와 상단 바를 포함한 화면 전체**를 가리킨다.
- 코드는 `src/preview/SlidePreviewArea.tsx`(컴포넌트 `SlidePreviewArea`)와 CSS 클래스 `.slide-preview-area`, `.slide-preview-area-frame`, `.slide-preview-area-slide`로 바꿨다.
- 용어 정의는 `docs/glossary.md`에 있고, 용어사전에는 쓰지 않는 용어를 적지 않는다.

**결과**
- 이전 ADR([261007_001])의 "1920×1080 고정 스테이지"라는 표현은 당시 기록이라 고치지 않았다.

## ADR-6. Node.js 버전 범위

**상태**: 확정

**결정**
- Node.js는 **`^20.19.0 || >=22.12.0`**을 지원 범위로 한다. 사용하는 도구(Vite 8, `@vitejs/plugin-react` 6, rolldown)가 요구하는 최소 버전이다.
- `package.json`의 `engines.node`와 `.npmrc`의 `engine-strict=true`로 지원 범위보다 낮은 버전에서는 `npm install`이 오류로 멈추게 한다.
- `.nvmrc`는 직접 확인한 버전 `24.19.0`을 알리는 용도로 두고 강제하지 않는다.
- npm 자체의 버전은 고정하지 않는다.

**결과**
- 직접 실행해 본 버전은 v24.19.0뿐이다. 그보다 낮은 버전(v20, v22)은 의존성이 지원한다고 밝힌 범위일 뿐 이 프로젝트에서 시험하지 않았다.
- 처음에는 `>=24.19.0 <25`로 좁게 고정했으나 의존성이 요구하는 최소 버전으로 풀었다.

## ADR-7. 저장소 운영

**상태**: 확정

**결정**
- 도구 저장소는 **GitHub 비공개(private) 저장소** `https://github.com/sehoon-pyo/course-maker`로 둔다. 기본 브랜치는 **`main`**이다.
- 이 프로젝트는 **저작권자가 사용을 승인한 사람만** 사용할 수 있다(README에 명시). 별도의 `LICENSE` 파일은 만들지 않는다. 승인한 사람은 저장소에 초대한다.
- README는 clone 주소와 "비공개 저장소이며 초대받은 계정으로 로그인해야 한다"는 안내를 담는다.
- slide 폴더 이름은 `sl.N_이름`으로 확정한다([261007_002] ADR-2에 반영).
- 폰트(NanumSquare)의 배포처는 네이버 나눔글꼴(https://hangeul.naver.com/fonts/search?f=nanum)이며 이용 조건은 그 안내를 따른다.

**결과**
- 비공개 저장소라도 커밋 이력과 작성자 이메일은 저장소에 기록되고, 초대받은 사람에게 보인다.
- `courses/`에서는 `sample`, `sample2`만 올라가고 나머지 강의는 강의별 별도 저장소로 관리한다([261007_003] ADR-2).

## ADR-8. 인라인 서식은 `t` 템플릿으로 쓴다

**상태**: 확정, 구현됨 ([261007_001] ADR-3의 작성 방식을 대체. `experiment/tagged-template` 브랜치에서 구현해 `main`에 합침)

**맥락**
배열 방식은 `"타입은 "`처럼 문자열 끝의 공백을 직접 챙겨야 하고 문장이 여러 조각으로 읽혀 불편하다. 문자열 안에 표시 문법(`[[동적|green]]`, `**굵게**`)을 쓰는 방식은 파서와 이스케이프가 필요하고 색 이름 같은 값을 타입 검사로 걸러낼 수 없다.

**결정**
- 한 문장 안에서 서식을 섞을 때는 **태그드 템플릿 `t`**로 쓴다.
  ```ts
  t`타입은 ${badge("동적", "green")}으로 결정된다`
  ```
- `${ }` 안에는 `badge`, `bold`, `code` 같은 인라인 요소(`Inline`)나 문자열만 넣을 수 있고, 다른 값은 타입 검사가 막는다.
- 서식이 없는 문장은 `t` 없이 일반 문자열 `"..."`로 쓴다.
- `t`는 글자 조각과 `${ }`의 값을 글에 적힌 순서대로 끼워 넣어, 문자열과 인라인 요소를 섞은 배열(`Inline[]`)을 돌려준다. 타입(`Inline`, `Sentence`), 헬퍼, 렌더링(`Inlines`) 구조는 [261007_001] ADR-3에서 바뀌지 않는다.

**결과**
- 파서가 필요 없고, 공백을 글 안에 그대로 쓸 수 있으며, 색 이름 등은 타입 검사를 받는다.
- 배열 항목이 PPTX 텍스트 run에 1:1로 대응하는 구조가 그대로 유지된다.
- 이 결정에 따라 기존 샘플 슬라이드(`sample`, `sample2`)의 배열 방식을 모두 `t`로 옮겼다. 옮기기 전과 화면 결과(서버 렌더링 HTML)가 같음을 17장 모두 확인했다.
- 구현 브랜치는 `main`에 합친 뒤 삭제했다.
