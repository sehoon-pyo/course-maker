## ADR-5. `badge()`는 없애고 강조로 바꾸며, 문장 안에 칩을 인라인으로 넣을 수 있게 한다

**상태**: 확정, 구현 전 ([261007_001] ADR-3의 인라인 서식에서 `badge()`를 없앰. [261007_004] ADR-11이 미뤄 둔 `badge()`, `code()`가 든 문단의 PPTX 내보내기를 정함)

**결정**
- **`badge()`는 없애고 강조(굵게 + 글자색)로 바꾼다.** 뱃지 정렬(`vertical-align`)은 강조로 바꿀 때 함께 정리한다.
- 강조와 `code()`는 PPTX의 **런 서식**으로 내보낸다. 문단당 텍스트박스 하나를 유지한다.
- **문장 안에 칩을 인라인으로 넣을 수 있게 한다.** 칩이 있는 문단만, 미리보기(HTML)의 줄바꿈과 조각 위치를 브라우저에서 측정해 줄과 조각 단위로 쪼갠다: 칩 앞 글(텍스트박스, 자동 줄바꿈 끔), 칩(둥근 사각형 + 아이콘 + 글자), 칩 뒤 글. 조각마다 측정한 왼쪽 좌표에서 시작한다.
- 칩이 있는 문단은 문단 하나로 편집할 수 없다는 예외를 둔다.

**결과**
- 뱃지의 PPTX 위치(글꼴 지표에 의존)와 pill 도형 표현이 필요 없어진다.
- 확인하지 못함: PowerPoint에서 칩 문단에 겹침이나 틈이 생기는지는 구현 때 확인한다.
- 기존 샘플의 `badge()` 사용은 구현할 때 함께 바꾼다.

## ADR-6. 자유형 도형과 바깥 그림자는 PPTX 도형 속성으로 내보낸다

**상태**: 확정, 구현 전 ([261007_001] ADR-4의 "복잡한 그림자는 PNG로 처리"를 장식 도형의 바깥 그림자에 대해서는 적용하지 않도록 좁힘)

**결정**
- 자유형은 `a:custGeom`으로 쓴다. SVG path의 `M L C H V Z`가 `moveTo lnTo cubicBezTo close`에 대응한다.
- 바깥 그림자는 `a:outerShdw`로 쓴다. 장식 도형의 그림자(번짐 80px, 거리 36px, 방향 45°, 검정 23%)를 **이미지로 만들지 않는다.** 그라데이션 등 다른 효과는 [261007_001] ADR-4 그대로이다.
- **도형 XML에 `p:style`을 두지 않는다.** 테마의 `effectRef`가 그림자 없는 도형에 테마 그림자를 붙이기 때문이다. 대신 채움, 선, 글자 색과 글꼴을 항상 명시한다.

**결과**
- 2026-10-08 임시 exporter(python-pptx)로 default 마스터 `title` layout의 장식 도형 2개를 만들어 PowerPoint로 렌더링해 확인했다. PowerPoint가 수정 없이 열었고 그림자가 그려졌다.
- 한계: 미리보기의 그림자는 PPTX보다 번짐이 넓고 연하다. `blur / 2` 환산 때문으로 추정하며 확인하지 못했다.
- 확인하지 못함: 글자가 든 도형에서 `p:style`(`fontRef`)을 제거했을 때의 영향.

## ADR-7. 글로우는 PPTX의 `a:glow`로 내보낸다

**상태**: 확정, 구현 전 ([261008_002] ADR-5의 글로우를 PPTX에 대응시키는 방식을 정함)

**결정**
- 도형의 글로우는 `spPr`의 `a:effectLst/a:glow`, 글자의 글로우는 `a:rPr`의 `a:effectLst/a:glow`(`a:solidFill` 뒤)로 쓴다.
- `rad`는 반경이며 px × 6350 EMU로 환산한다.
- 글로우와 바깥 그림자는 한 도형에 같이 걸어도 둘 다 그려진다.

**결과**
- 2026-10-08 임시 exporter로 `Stamp`와 같은 값(도형 4px, 글자 10px, 알파 40%)을 만들어 PowerPoint로 확인했다. 시험의 글자는 NanumSquare가 아니었다.
- 한계: 글자 글로우는 같은 반경이어도 도형 글로우보다 눈에 띄게 좁게 번진다(30px에서 글자 한 글자 기준 한쪽 약 8px로 보임, 정밀 측정은 아님). 미리보기와 번짐의 진하기를 픽셀로 비교하지는 못했다.

## ADR-8. PowerPoint에서 쓰는 폰트 이름

**상태**: 확정, 구현 전 (2026-10-08 폰트 파일의 name table로 확인함)

**결정**
- R은 `NanumSquare`, B는 `NanumSquare Bold`로 쓴다. **`b="1"`(굵게 속성)은 쓰지 않는다.**
- 한글 이름(`나눔스퀘어`)은 시스템 언어에 따라 달라질 수 있어 쓰지 않는다.

**결과**
- `assets/fonts`의 두 파일 name table(Windows 플랫폼)에서 R은 패밀리 `NanumSquare`/`Regular`, B는 패밀리 `NanumSquare Bold`/`Regular`이다. B가 별도 패밀리 이름이라 `NanumSquare`에 `b="1"`을 주면 PowerPoint가 B 파일을 잇지 못하고 R을 굵게 만든다(글자 폭이 R과 같아서 가짜 굵게로 판단). `NanumSquare Bold`는 b 값과 관계없이 진짜 B로 그려진다.
- 한계: 시험한 PC에는 NanumSquare가 10개 파일로 설치되어 있어(저장소의 2개와 같은지 확인하지 못함) 렌더링은 설치된 폰트로 했다. 폰트가 없는 PC에서는 다른 글꼴로 대체되므로 PPTX 납품 때 폰트 동봉이 필요하다.

## ADR-9. HTML과 PPTX 비교 진단 도구를 export와 함께 만든다

**상태**: 확정, 구현 전

**결정**
- export를 만들 때 진단 도구를 함께 만든다.
  1. HTML 좌표와 PPTX 도형 좌표를 수치로 비교한다.
  2. 슬라이드별로 HTML과 PPTX를 나란히 놓은 이미지와 차이 이미지를 한 페이지로 만든다.
- 판정은 사람이 한다. 이미지 점수는 어긋난 슬라이드를 찾는 정렬용이며 임계값은 sample로 정한다.
- PPTX 렌더링은 PowerPoint(Windows)로 한다.
- 자동 합격/불합격 테스트는 만들지 않는다. 문서에는 export 도구의 일부로 적는다(`CLAUDE.md`의 "테스트와 린트는 없다"와 같은 방침).

**결과**
- 근거: ADR-6, 7, 8의 시험에서 같은 절차(임시 exporter → PowerPoint COM으로 PNG → Chrome headless로 미리보기 캡처)로 눈 비교를 했고, 그림자와 글로우의 번짐 차이는 점수로는 구분하기 어렵다.
- 미해결: 미리보기를 UI 없이 슬라이드만 찍는 캡처 모드가 필요하다.

## ADR-10. 마스터는 진짜 PPTX 마스터로 내보낸다

**상태**: 확정, 구현 전 ([261007_004] ADR-11의 "마스터를 진짜 PPTX 마스터로 올린다"를 구체화함)

**결정**
- 토큰은 테마의 색과 글꼴(major `NanumSquare Bold`, minor `NanumSquare`)로, 슬롯은 플레이스홀더로, 층과 장식은 layout 도형으로 옮긴다.
- **슬롯의 글자 속성(크기, 색, 정렬, 앵커)은 layout 플레이스홀더에 두고 슬라이드는 상속하며, 다른 값만 덮어쓴다.**
- 자유 배치 요소는 플레이스홀더가 아니며 `p:style` 없이 항상 명시한다.

**결과**
- 2026-10-08 임시 exporter(python-pptx)로 `title` layout 하나를 시험해 PowerPoint가 마스터, layout, 플레이스홀더로 인식하고 새 슬라이드를 추가하면 플레이스홀더가 따라옴을 확인했다.
- 확인하지 못함: 나머지 layout 3개, `list`와 `free` 슬롯, 로고 이미지, 고정 문구, 토큰 10개 전체의 대응, 생성 라이브러리(python-pptx로 가능은 확인, `pptxgenjs`는 시험하지 않음).

## ADR-12. 요소의 디자인은 마스터의 `tokens`(CSS 변수)로만 선언한다

**상태**: 확정, 구현됨 ([261007_004] ADR-8 "결과"에서 정하지 않았던, 요소가 마스터의 디자인을 어떻게 선언하는지를 해결함)

**결정**
- `defineMaster`에 `elements` 같은 항목은 두지 않는다.
- 요소의 CSS는 변수만 읽고, 값은 마스터의 `tokens`가 정한다(`Chip`은 `--chip-*`, `PromptBox`는 `--promptbox-*`).
- 필수 토큰 10개(`REQUIRED_TOKENS`)는 늘리지 않는다. `--chip-*`, `--promptbox-*`는 해당 요소를 쓸 때만 필요하다.
- 마스터가 이 변수를 정하지 않으면 도구가 채우는 기본값은 없다.

**결과**
- `styles.css`는 이 변수를 `var(--chip-height)`처럼 대체값 없이 읽고 `:root`에도 정의하지 않는다(2026-10-08 코드 확인). 변수가 없으면 그 속성이 적용되지 않아 속성의 초기값으로 그려진다.

## ADR-13. `Image`의 속성은 현재 구현을 확정한다

**상태**: 확정, 구현됨 ([261007_004] ADR-7이 `Image`의 속성을 적지 않은 것을 채움)

**결정**
- 속성: `src`(필수, 강의 폴더의 이미지를 import한 주소), `alt`(선택, 기본 빈 문자열), `at`(선택. 없으면 슬롯, 있으면 절대 위치), `fit`(`contain`, `cover`, `fill`. 기본 `contain`이며 `at`에 `w`, `h`를 둘 다 줬을 때만 의미가 있음).
- 이미지 파일은 강의의 `assets/`에 둔다.
- 그 밖의 속성(`rotate`, 모서리 둥글림, 투명도, 그림자 등)은 필요할 때 추가한다.

**결과**
- PPTX export에서 `fit`(특히 `cover`의 잘림)을 옮기는 방식은 export 때 정한다.

## ADR-14. 슬롯의 넘침은 자르지 않고 경고하며, 경고는 상단 바에 모은다

**상태**: 확정, 일부 구현됨 (콘솔 경고와 `--slot-gap`은 구현됨. 상단 바 신호등과 `PromptBox`의 넘침 표시는 구현 전)

**결정**
- 슬롯 안 내용이 넘쳐도 자동으로 줄이거나 자르지 않는다. 슬롯 박스 밖으로 그대로 그리고 경고만 한다. 목차의 `list` 슬롯은 예외로 `rows`를 넘는 항목을 표시하지 않고 경고한다.
- 한 슬롯에 요소가 여러 개일 때의 간격은 슬롯 단위의 토큰 `--slot-gap` 하나로 정한다. 요소별 간격은 필요할 때 추가한다.
- **콘솔에 나오는 경고 전체**(슬롯 넘침, `list` 슬롯 넘침, 마스터 오류, `meta.ts`와 폴더 불일치 등)를 미리보기 상단 바에 모은다. 오류가 있으면 빨간 신호등이 켜지고, 눌러서 내용을 볼 수 있다.
- `PromptBox`는 지금 `overflow: hidden`으로 잘린다. 이것도 "그려서 경고"하는 방식으로 바꾼다.

**결과**
- 넘침이 PPTX에서 어떻게 보이는지는 export 때 확인한다.

## ADR-15. 여러 줄은 인라인 헬퍼 `br()`로 쓰고, `PromptBox`의 안쪽 배치는 현재 구조를 유지한다

**상태**: 확정, 구현됨 (`br()`은 [`[261011_001]_adr.md`](./[261011_001]_adr.md) ADR-3으로 구현함). 안쪽 배치는 구현됨 (글 블록의 정렬과 여백은 [`[261011_001]_adr.md`](./[261011_001]_adr.md) ADR-5로 바뀜) ([261007_004] ADR-8 "결과"의 "안쪽 배치 규칙, 여러 줄 처리는 정하지 않았다"를 해결함)

**결정**
- 줄바꿈은 인라인 헬퍼 `br()`로 넣는다(``t`첫째 줄${br()}둘째 줄` ``). 문자열의 `\n`과 CSS `white-space: pre-line`은 쓰지 않는다.
- 이유: 줄바꿈이 CSS가 아니라 문장 데이터에 있어 HTML과 PPTX(`a:br`)의 결과가 어긋날 여지가 적고, 소스를 여러 줄로 써도 의도치 않게 줄이 바뀌지 않으며, `badge()` 같은 헬퍼로 서식을 쓰는 규칙과 맞는다.
- `br()`은 `PromptBox`만이 아니라 `Sentence`를 받는 모든 요소(`Paragraph`, `Bullets` 등)에서 쓸 수 있는 인라인 서식이다.
- `PromptBox`의 안쪽 배치는 현재 구조를 확정한다. 머리(아이콘, 있을 때만), 구분선, 글 영역이 세로로 쌓이고 값은 `--promptbox-*` 토큰으로 정한다. 새 규칙은 만들지 않는다.

**결과**
- 인라인 조각 타입을 어떻게 더할지는 `Inlines`를 읽고 구현 때 정한다.

## ADR-16. 슬라이드 번호 슬롯만 남기고, 날짜와 바닥글은 만들지 않는다

**상태**: 확정, 구현 전 ([261007_004] ADR-12의 "날짜, 바닥글, 슬라이드 번호 슬롯은 넣지 않는다. 나중에 한다"를 날짜와 바닥글은 만들지 않고 번호 슬롯만 남기는 것으로 좁힘. [261008_002] ADR-1에서 쪽번호 layout(번호 슬롯)을 만들 때 추가한다고 한 슬라이드 위 페이지 번호를 구체화함)

**결정**
- 날짜와 바닥글 슬롯은 만들지 않는다.
- 번호 슬롯은 layout에 포함한다. 표시 형식은 `n / N`이고 기준은 [261008_002] ADR-1이다(chapter 안에서 1부터, 숨김 슬라이드는 번호가 없고 `N`은 숨김을 뺀 수).
- 슬라이드에서 번호를 빼는 방법은 슬라이드 속성 `<Slide number={false}>`이다. 기본은 넣는 것이다.
- 번호 슬롯은 `content`, `title-only` layout에 포함하고 `title`, `toc`에는 두지 않는다.
- 숨김 슬라이드 위에서는 번호 슬롯에 "숨김"이라고 표시한다.
- 슬롯 모양: 기존 PPTX의 위치(`x1356 y1001 w432 h58`), 24px, 오른쪽 정렬, 세로 가운데, 색은 토큰 `muted`(`--color-muted`)이다. 적당히 정한 값이다.

**결과**
- 기존 PPTX는 컨텐츠 layout에만 번호 슬롯이 있었다는 기록이 있고, 나머지 layout은 확인하지 못했다. `title-only`에 포함하는 것은 이 결정으로 정했다.
- PPTX export에서 번호를 내보내는 방식은 export 때 정한다.
- 구현할 때 `README.md`와 `CLAUDE.md`의 "날짜/바닥글/슬라이드 번호는 아직 없다"를 "슬라이드 번호"로 줄이고 `docs/github.md`의 마일스톤 `날짜, 바닥글, 번호`를 `슬라이드 번호`로 바꾼다.

## ADR-17. 표만 로드맵에 남기고, 나머지는 지금 만들지 않는다

**상태**: 확정 ([261007_004] ADR-12에서 만들지 않기로 한 `Group`, 자동 배치, 표, 층 사이에 끼우는 앵커를 표만 마일스톤에 올리고 나머지는 삭제하는 것으로 정리함)

**결정**
- **표**는 마일스톤 `표 요소`에 둔다. HTML `table`과 PPTX `a:tbl`이 구조가 직접 대응하고 `colspan`, `rowspan`도 `gridSpan`, `rowSpan`에 대응한다([261007_001] 노트).
- **`group`, 자동 배치(`Row`/`Column`), 층의 앵커(`above` 등)**는 지금 필요하지 않아 노트와 문서에서 지운다. 필요한 사례가 나오면 새 항목으로 올린다.
- 목차 layout의 번호 칸과 제목 칸 색 `#6C93C6`은 쓰지 않는다. 용도를 확인하지 못했다. 확인되면 다시 연다.
- **화면에서 고쳐 TSX에 저장하는 기능**은 지금 만들지 않고 나중에 마일스톤으로 올린다. 만들 때 [261007_003] ADR-1을 대체하는 새 ADR을 먼저 쓴다. 마일스톤은 이 기능을 구현하기 직전에 추가한다.

**결과**
- 확인하지 못함: 기존 PPTX의 표 사용 빈도.
- 마일스톤 이름은 `슬라이드 요소 확장`에서 `표 요소`로 바꾸었다.

## ADR-20. 도구는 clone으로 받아 업데이트하고, 강의는 별도 저장소를 `default-course` template으로 만든다

**상태**: 확정, 일부 구현 전 ([261007_003] ADR-2의 "강의는 강의별 별도 저장소"를 구체화함. template 저장소는 아직 만들지 않음)

**맥락**
강의를 도구와 같은 저장소에 두는 fork 방식을 검토했으나 채택하지 않았다. 사용자가 도구를 가져간 뒤에는 그 강사의 스타일대로 계속 가므로 원본 이력을 이어 갈 이유가 없고, 도구는 계속 개선되므로 업데이트는 받아야 한다.

**결정**
- **fork는 쓰지 않는다.**
- **도구(`course-maker`)는 사용자가 clone으로 받고 `git pull`로 업데이트한다.**
- 강의는 도구 저장소와 별도의 git 저장소이고, 도구 저장소의 `.gitignore`는 `courses/*`를 무시하고 예제(`sample`, `sample2`)만 추적하는 지금 규칙을 유지한다.
- **강의의 초깃값은 별도의 `default-course` template 저장소**로 만든다. 사용자는 `courses/` 폴더 안에서 이 template으로 자기 강의 저장소를 만들어 clone한다.
- **template은 복사한 시점에 고정된다.** 그 뒤 template이 바뀌어도 받지 않는다.
- 지금의 `courses/default-course/`는 임시용이다(`.gitignore` 때문에 도구 저장소가 추적하지 않는다).
- 공개 범위: 지금은 public(누구든 볼 수 있고 가져가도 된다)이고, 필요한 시점에 private로 바꿔 collaborator에게만 공유한다. `README.md`의 사용 조건("승인한 사람만 사용")과 "비공개" 안내는 뺐다.
- 폰트는 무료 폰트만 쓴다.

**결과**
- 정하지 않았다: `default-course` template 저장소를 만드는 시점과 이름.
- `README.md` 4번에 도구 업데이트 방법(`git pull`)을 한 줄로 적었다.

## ADR-21. 마스터는 강의가 가지고, 요소와 폰트는 도구에 둔다

**상태**: 확정, 구현됨 ([261007_003] ADR-3의 "도구가 제공하는 마스터는 `src/masters/{id}/`에 둔다"와 "없으면 `default`"를 도구가 마스터를 제공하지 않는 것으로 바꿈. [261007_004] ADR-10의 `default` 마스터 위치를 옮김)

**결정**
- 도구(`src/masters/`)는 마스터를 제공하지 않는다. 기본 마스터를 `courses/sample/masters/default/`와 `courses/default-course/masters/default/`로 옮겼다. 마스터의 assets(로고)는 마스터와 함께 간다.
- 마스터 id는 `default` 그대로이고 기본 id(`DEFAULT_MASTER_ID`)도 `default`이다. 폴더가 `masters/` 아래에 있으므로 이름이 혼동되지 않는다.
- 마스터 id 조회 순서(① 강의 `masters/` → ② `src/masters/`)는 코드를 바꾸지 않았다. `src/masters/`에 마스터를 두면 모든 강의가 쓰는 마스터로 읽힌다.
- 요소(`src/elements/`), 마스터 로딩 코드, 폰트(`assets/fonts`)는 도구에 둔다. 강의마다 복사하면 코드와 용량이 중복된다. 강의 전용 요소는 지금처럼 강의의 `elements/`에 둔다.
- 새 강의는 `default-course` template(ADR-20)에서 시작하고, 그 안에 마스터가 들어 있다.
- 강의에 마스터가 없으면 "마스터를 찾을 수 없습니다" 오류에 마스터 폴더의 위치(`courses/{강의}/masters/{id}/index.tsx`)를 확인하라는 안내를 붙인다(구현함). 해결 방법(복사 등)은 안내하지 않는다.

**결과**
- `sample`은 마스터 복사본을 갖는다. 같은 마스터가 `sample`과 `default-course`에 두 벌 있다.
- 2026-10-08 확인: `npm run typecheck`와 `npm run build` 통과, 사용자가 `sample`과 `default-course`의 미리보기가 잘 열리는 것을 확인했다.

## ADR-25. 개발 서버는 `localhost`로 접속한다
