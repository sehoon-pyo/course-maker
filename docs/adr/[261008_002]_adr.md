## ADR-1. 번호와 이동은 chapter 기준이다

**상태**: 확정, 구현됨 ([261007_003] ADR-4의 "이전/다음, `n / 전체`의 기준은 정하지 않음"을 정함. [261008_001] ADR-4의 "숨김 슬라이드는 이전/다음과 `n / 전체`에 포함"과 하단 안내 부분을 대체함)

**맥락**
chapter는 실제 파일로 배포하는 단위(chapter 하나 = 단일 HTML 하나)이다. 번호와 이동이 강의 전체를 기준으로 되어 있으면 chapter를 파일로 내보냈을 때와 뷰어의 번호가 맞지 않는다.

**결정**
- **번호는 chapter 안에서 1부터 이어서 매긴다.** `head` → section의 슬라이드 → `tail` 순서이다(ADR-2). section이 바뀌어도 번호가 이어진다. 대제목과 목차도 번호를 매긴다.
- **숨김 슬라이드에는 번호를 매기지 않는다.** 번호는 숨김을 건너뛰고 이어진다(내보낸 파일에서 숨김이 빠져도 번호가 같도록).
- 뷰어의 **사이드바**는 이 번호를 보여 준다(숨김 슬라이드는 번호 없이 "숨김" 표시).
- 뷰어의 **하단**은 `n / N`이다(`N`은 숨김을 뺀 chapter의 슬라이드 수). 숨김 슬라이드 위에서는 `숨김 / N`이다.
- 숨김 슬라이드가 있을 때 하단에 따로 안내문을 보이지 않는다.
- 하단의 버튼은 `<< 이전 챕터`, `< 이전`, `다음 >`, `다음 챕터 >>`이다.
  - `< 이전`, `다음 >`은 슬라이드 한 장 이동이고 **chapter 끝에서 멈춘다**(숨김 슬라이드로도 오갈 수 있다).
  - `<< 이전 챕터`, `다음 챕터 >>`는 이전/다음 chapter의 **첫 슬라이드**로 간다. 첫 chapter의 `<<`와 마지막 chapter의 `>>`는 비활성이다. 슬라이드가 없는 chapter는 건너뛴다.
- 키: `←`, `→`, `PageUp`, `PageDown`은 `< 이전`, `다음 >`과 같고, **`Ctrl + ←`, `Ctrl + →`는 이전/다음 chapter**이다.
- 슬라이드 위에 그리는 페이지 번호는 쪽번호 layout(번호 슬롯)을 만들 때 추가한다([261007_004] ADR-12 그대로).

**결과**
- 강의를 고를 때와 chapter를 고를 때는 그 강의, chapter의 첫 슬라이드로 간다(변함 없음).
- 이전에는 `<`, `>`가 강의 끝까지 chapter를 넘었으나 이제 chapter 끝에서 멈춘다.

## ADR-2. chapter는 `head`와 `tail` 슬라이드를 가질 수 있다

**상태**: 확정, 구현됨 ([261008_001] ADR-1의 "순서는 상위 `meta.ts`의 배열"을 chapter의 앞뒤 슬라이드로 넓힘. [261007_002] ADR-1의 계층 `course → chapter → section → slide`에서 슬라이드가 section 밖에도 있을 수 있게 함)

**결정**
- 대제목과 목차는 chapter 전체의 앞머리이지 어느 section의 일부가 아니다. chapter `meta.ts`에 **section 앞에 오는 슬라이드 `head`와 뒤에 오는 슬라이드 `tail`**을 둔다.
  ```ts
  // courses/{강의}/ch.3_master/meta.ts
  export default {
    title: "3장 마스터와 요소",
    head: ["sl.1_title", "sl.2_toc"],                    // section 앞 (대제목, 목차)
    sections: ["sec.1_layouts", "sec.2_elements"],
    tail: ["sl.9_progress"],                             // section 뒤 (진행 현황 등)
  } satisfies ChapterMeta;
  ```
- `head`와 `tail`은 선택이다. 항목의 형식은 section의 `slides`와 같다(문자열 또는 `{ id, hidden }`). 슬라이드 폴더는 chapter 폴더 바로 아래에 둔다.
- 순서는 `head` → `sections` → `tail`이다. 사이드바는 `head`를 section 제목 없이 맨 위에, `tail`을 맨 아래에 보인다.
- `SECTION n` 번호는 section만 센다. 목차(`Toc`)가 채우는 항목도 section만이다.
- 상단 바의 위치 표시는 `chapter / 슬라이드`이다(section이 없음). URL 해시는 `#/{강의}/{chapter}/{슬라이드}`이다.
- `head`, `tail`도 section과 같은 규칙으로 배열과 폴더가 어긋나면 경고한다([261008_001] ADR-3).

**결과**
- 슬라이드가 `courses/{강의}/{chapter}/{슬라이드}/index.tsx`에 있으면 강의 요소를 가져오는 상대 경로가 한 단계 짧다. section 안의 슬라이드는 `../../../elements`, chapter 바로 아래의 슬라이드는 `../../elements`이다([261007_004] ADR-9의 경로 규칙).
- chapter 바로 아래의 슬라이드를 읽는 경로 모양이 마스터(`courses/{강의}/masters/{id}/index.tsx`)와 같으므로, 강의의 `chapters` 배열에 있는 chapter 폴더 아래만 슬라이드로 읽는다.

## ADR-3. 뱃지는 본문 글자의 중심선에 맞춘다

**상태**: 확정, 구현됨

**결정**
- 문장 안의 뱃지(`badge()`)는 기준선에 앉으면 본문 글자의 중심선보다 아래로 처진다(본문 48px에서 4.3px). `.badge`에 `vertical-align: 0.1em`을 준다.
- 값은 화면에서 0.06em ~ 0.15em, `middle`을 시험해서 정했다. 0.11em이면 한글 문장의 중심과 정확히 맞고(0.1px), 숫자와 영문 소문자가 섞인 줄에서는 뱃지가 높아 보여서 0.10em으로 정했다(한글 중심과 0.5px 차이).
- em 단위라 본문 글자 크기가 달라져도 같은 비율로 맞는다.

**결과**
- 뱃지를 PPTX로 내보낼 때의 위치는 글꼴 지표에 의존하므로 export를 만들 때 따로 정한다.

## ADR-4. 칩의 아이콘, 강의 전용 칩, 프롬프트 박스의 아이콘

**상태**: 확정, 구현됨 ([261007_004] ADR-8, 9를 구체화함)

**결정**
- 도구의 `Chip`은 아이콘을 줄 수도, 안 줄 수도 있다. **아이콘은 정사각형 칸(`--chip-icon-size`) 안에 비율을 지켜 맞춘다**(가로로 긴 claude 이미지도 칸을 넘지 않는다).
- **`PromptBox`는 `icon`을 받아서 쓴다.** `ClaudePromptBox` 같은 변형은 만들지 않는다.
- 아이콘이 정해진 칩은 **강의 전용 요소**로 만든다. sample 강의의 `elements/`에 `ClaudeChip`, `TerminalChip`, `FileChip`이 있다(도구의 `Chip`에 아이콘을 정해 둔 변형).
- 아이콘의 모양은 예시 PPTX(`PPT 도형.pptx`)의 것을 따른다. 도구가 아니라 강의의 `assets/`에 둔다.
  - 아이콘은 PPTX의 이미지를 그대로 넣지 않고 **같은 모양으로 svg를 그려서** 쓴다(`icon-claude.svg`, `icon-terminal.svg`, `icon-file.svg`). claude는 원본(204×192)에서 **위쪽 16.753%, 아래쪽 11.651%를 자른**(PPTX의 `srcRect`) 204×138(비율 1.478)의 픽셀 모양을 화소 좌표로 읽어 그렸고(색 `#D97757`), 배경은 투명하다. 칩에서는 56×37.9px, 프롬프트 박스에서는 64×43px로 놓인다.
  - 터미널(원본 64×64)과 파일(원본 512×512)은 원본 이미지를 눈으로 비교해 선 굵기와 모서리를 맞췄다. 화소 단위로 같지는 않다.
- 처음에 임의로 그렸던 아이콘(별, 터미널, 파일 svg)은 PPTX와 모양이 달라 지웠고, 위의 svg가 그 자리를 대신한다.
- 샘플의 칩: `/bg`, `/resume`, `ctrl + x`는 `ClaudeChip`, `claude agents`는 `TerminalChip`, `CLAUDE.md`는 `FileChip`이고, 아이콘 없는 `Chip`도 둔다.

**결과**
- claude 캐릭터는 제3자의 것일 수 있다. 사용자가 PPTX에서 쓰도록 했고, 도구의 `src/`가 아니라 강의(sample)의 `assets/`에 있다.

## ADR-5. 글로우(네온)는 도형과 글자의 일반 속성이고, 도장은 강의 전용 요소이다

**상태**: 확정, 구현됨 (`Stamp`는 [261008_004] ADR-8로 도구 요소가 됨("강의 전용" 서술을 대체))

**결정**
- `Shape`에 `glow={{ radius, color }}`(도형의 글로우), 글자 속성(`TextStyle`)에 `glow`(글자의 글로우)를 둔다. PowerPoint의 도형 효과 "네온"과 글자 효과 "네온"에 대응한다. 반경은 px, 색은 알파를 포함한 값이거나 토큰 이름이다.
- 도형의 글로우는 도형(svg)에만 걸고(`filter: drop-shadow`), 글자의 글로우는 `text-shadow`로 건다. 채움이 없는 도형은 테두리를 따라 번진다.
- **도장은 강의 전용 요소(`Stamp`)로 먼저 만든다.** sample 강의의 `elements/Stamp.tsx`이고, 예시 PPT의 마지막 장에 있는 "완료" 도장의 값을 쓴다: 둥근 사각형 120×57.1px, 35.09° 회전, 채움 없음, 선과 글자 `#00B0F0`(선 1.5pt = 3px), 도형 글로우 4px(파랑 `#1567F4`, 알파 40%), 글자 글로우 10px(`#00B0F0`, 알파 40%), 글자 36px(PPTX의 기본 크기).
- 샘플: `ch.3_master`의 `tail` 슬라이드(`sl.9_progress`)가 예시 PPT의 마지막 장("현재 우리는")의 진행 현황을 따라 만든 것이다(아래 화살표 배경, 단계 5개, 끝난 두 단계는 검정 29%로 덮고 도장).

**결과**
- 글로우의 번짐 모양은 CSS와 PowerPoint가 같지 않다. 값(반경, 색, 알파)은 PPTX 그대로이고 눈으로 비교해 확인했다.
- PPTX export에서는 `a:glow`로 대응한다(PowerPoint 기본 효과). export는 아직 없다.
