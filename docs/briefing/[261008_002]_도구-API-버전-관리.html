노트 261008_003 · 항목 21

도구 API 버전 관리

도구를 고쳤을 때 강의 저장소가 깨지는 문제를 어떻게 다룰지 정하는 항목입니다. 지금은 "강의가 늘어 문제가 보일 때 정한다"로 보류되어 있습니다.

결론부터. 이미 한 번 깨지는 변경이 있었지만(아래), 강의 저장소가 이 도구와 같은 사람이 쓰는 로컬 저장소라 지금 버전 관리 체계를 만들 비용이 더 큽니다. 보류를 유지하되 "깨지는 변경은 ADR에 적는다"는 최소 규칙만 두는 안을 권합니다.

왜 문제가 되는가

강의는 도구와 별도의 git 저장소(courses/내강의/)에 있고, 그 안의 코드가 도구에 의존합니다. 도구가 바뀌면 강의가 깨질 수 있다는 점은 ADR 261007_003과 261008_001에 이미 주의로 적혀 있습니다.

강의가 의존하는 것바뀌면 깨지는 예
@/elements의 요소와 속성속성 이름을 바꾸거나 없애면 슬라이드 TSX가 타입 오류
강의 전용 마스터의 defineMaster와 tokens필수 토큰(REQUIRED_TOKENS, 10개)을 늘리면 기존 마스터가 오류를 냄
meta.ts의 모양(chapters, sections, slides, head, tail)항목 형식이 바뀌면 목차가 비거나 경고

확인된 것과 확인되지 못한 것

내용상태근거
실제로 깨지는 변경이 이미 있었다확인함ADR 261008_001: 기존 강의의 meta.ts는 chapters, sections를 추가해야 읽힘
이 저장소가 추적하는 강의는 sample과 sample2뿐확인함courses/ 폴더 목록, CLAUDE.md
버전 표시가 없다확인함package.json의 version이 0.0.0, git 태그 없음
도구를 쓰는 다른 사람이나 강의 저장소의 수확인하지 못함이 저장소 밖(별도 저장소)이라 볼 수 없음. 말씀해 주셔야 함
변경 이력(CHANGELOG)을 따로 두는지확인하지 못함이번에 찾아보지 않음. ADR이 사실상 변경 기록 역할을 함

선택지

하는 일비용과 효과
A보류를 유지하고, 깨지는 변경은 ADR에 "강의에 필요한 수정"으로 적는다.새로 만들 것이 없음. 강의 수정 방법이 ADR에 남아 사람이 따라 고칠 수 있음.
B도구에 버전(package.json)을 올리고 깨지는 변경마다 올림. 변경 이력 파일을 둔다.어느 도구 버전에서 무엇이 깨졌는지 한 곳에서 보임. 올리고 쓰는 수고가 계속 듦.
C강의 meta.ts에 필요한 도구 버전을 적고, 맞지 않으면 미리보기에서 경고한다.깨지기 전에 알 수 있음. B가 먼저 있어야 하고 구현도 필요함(경고는 이미 있는 콘솔 경고 모으기와 같은 자리).
