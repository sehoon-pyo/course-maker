STEP 5는 무엇을 하는 단계인가

프로젝트(보드)와 저장소를 이어 주고 보드가 스스로 움직이게 하는 단계입니다. 확인해 보니 일부는 이미 되어 있어서, 남은 일이 문서에 적은 것보다 적습니다.

결론. 저장소와 프로젝트 링크는 이미 되어 있어서 제가 할 일이 없습니다. 남은 것은 웹에서 자동화 설정을 눈으로 확인하는 것과, 문서를 지금 프로젝트에 맞게 고치는 것입니다.

1. 프로젝트와 마일스톤, 이슈는 각각 무엇인가

  • 이슈: 해야 할 일 하나. 저장소 안에 만든다.
  • 마일스톤: 이슈를 목표별로 묶는 저장소 안의 상자(STEP 2에서 5개를 만들었다).
  • 프로젝트: 이슈와 PR을 한 화면에 모아 상태별로 보는 보드. 저장소 밖(내 계정 아래)에 있다.

저장소와 프로젝트는 서로 다른 곳에 있어서, 그냥 두면 이슈를 만들어도 보드에 나타나지 않는다. 이어 주는 일이 STEP 5이다.

2. STEP 5가 하는 두 가지

할 일하면 달라지는 것어떻게지금 상태
링크저장소의 Projects 탭에 이 보드가 보이고, 이슈를 만들 때 프로젝트를 고를 수 있다.gh project link (Claude)확인함 이미 연결되어 있다.
자동화이슈를 만들면 보드에 자동으로 올라오고, 닫으면 Done으로 옮겨진다. 손으로 옮기지 않아도 된다.웹 UI의 Workflows (사용자)확인하지 못함 켜졌는지는 모른다.

3. 확인한 것

  • 확인함프로젝트 course-maker(#1, 비공개)가 이 저장소의 프로젝트 목록에 이미 나온다. 링크는 끝난 상태이다.
  • 확인함보드에 항목이 3개 있다. 우리가 머지한 PR #1, #2, #3이고 모두 Done이다. 즉 PR은 이미 자동으로 올라오고 머지되면 Done이 되고 있다.
  • 확인함프로젝트의 Status 옵션은 Backlog / Ready / In progress / In review / Done 다섯 개이다. Priority(P0~P2)와 Size(XS~XL)도 이미 있다.
  • 확인함프로젝트에는 Milestone 칸이 기본으로 있다. 마일스톤별 표 보기를 만들 수 있다.
  • 확인하지 못함Auto-add 같은 자동화가 어떤 설정으로 켜져 있는지. gh로는 읽을 수 없고 웹에서만 볼 수 있다.
  • 확인하지 못함보기(Board, 마일스톤별 표)가 이미 있는지.

4. 사용자가 웹에서 할 일 (2~3분)

  1. 자동화 설정 확인

    • https://github.com/users/sehoon-pyo/projects/1 을 연다.
    • 오른쪽 위 ··· → Workflows를 연다.
    • "Item added to project", "Item closed", "Pull request merged"가 켜져 있는지 본다. 새 이슈가 자동으로 올라오려면 "Auto-add to project"(저장소 sehoon-pyo/course-maker)도 필요하다. 꺼져 있으면 켠다.

  2. 보기(View) 만들기 (선택)

    • 이슈가 아직 없어서 급하지 않다. 이슈를 올린 뒤(STEP 6)에 만들어도 된다.

5. 문서와 실제가 어긋난 곳

docs/github.md 6번이 만든 직후의 가정으로 쓰여 있어 지금 프로젝트와 다릅니다.

문서실제
Status는 Todo / In Progress / DoneBacklog / Ready / In progress / In review / Done
프로젝트는 항목 0개PR 3개가 Done으로 들어와 있음
저장소에 링크하는 명령이 필요이미 링크됨
Size는 필요하면 추가(S/M/L)이미 있음(XS/S/M/L/XL)
course-maker 저장소의 GitHub 설정 진행 중에 STEP 5를 설명하려고 만든 문서입니다. 입력은 이 브라우저에만 저장됩니다.
