BRIEFING 261010_001 · docs/github.md 10번 시작 순서의 5단계

이슈 목록과 마일스톤

노트 [261008_003]과 ADR [261008_003]의 미구현 항목을 이슈 13개로 묶고 마일스톤에 연결한 제안입니다. 이슈는 아직 하나도 만들지 않았습니다.

묶는 기준

docs/github.md 5-5의 규칙을 따랐습니다.

  • 지금 바로 구현할 수 있는 것은 이슈 하나씩 만듭니다.
  • export처럼 시점이 정해진 항목은 잘게 쪼개지 않고, 마일스톤마다 이슈 하나에 체크리스트로 묶습니다.
  • 결정이 남은 항목에는 needs-decision 라벨을 붙입니다.
  • 만든 뒤 노트의 행에 #번호만 추가합니다. 기존 문장은 고치지 않습니다.

확인한 것과 확인하지 못한 것

확인함: 노트와 ADR의 구현 상태(구현 전, 일부 구현), 마일스톤 5개의 이름(docs/github.md 4번), 라벨 체계(3번), 저장소의 .github/ 양식 파일.

확인하지 못함: 이 PC에 gh가 없어 GitHub의 실제 라벨, 마일스톤, 프로젝트가 만들어져 있는지는 보지 못했습니다. 마일스톤 날짜, 바닥글, 번호는 ADR-16에 따라 이름을 바꿔야 하는데, 문서에는 아직 바꾸지 않았다고 되어 있습니다. 이슈를 만들기 전에 gh를 설치하고 로그인해야 합니다.

마일스톤 요약

마일스톤이슈비고
단일 HTML export#A1기존
PPTX export#B1, #B2기존
PDF export#C1기존
표 요소#D1기존
날짜, 바닥글, 번호 → 슬라이드 번호#E1기존. ADR-16에 따라 이름을 바꿈(결정 1)
미리보기 개선#F1, #F2, #F3새로 만들기(결정 2)
인라인 서식 정리#G1, #G2, #G3새로 만들기(결정 3)
없음#H1저장소 운영 성격이라 마일스톤을 걸지 않음

이슈 번호(#A1 등)는 이 문서 안의 임시 이름입니다. GitHub에서 붙는 번호와 다릅니다.

이슈로 만들지 않는 것

  • 화면에서 고쳐 TSX에 저장하는 기능: ADR-17에 따라 구현 직전에 ADR과 마일스톤을 함께 만듭니다.
  • PowerPoint 원본과 눈으로 비교하는 일(노트 4번): 구현 항목이 아니라 확인 항목이라 제외했습니다. #B2 진단 도구가 생기면 거기서 합니다.
  • group, 자동 배치, 층 앵커, 목차 색 #6C93C6: ADR-17에서 만들지 않기로 했습니다.
