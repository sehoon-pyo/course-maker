### 이미 정해진 것 (ADR [261007_003] ADR-3, 용어사전)
- `slide-master`는 PowerPoint의 슬라이드 마스터와 같은 개념이고, 안에 `background`와 `layout`이 들어 있다. layout의 `background`는 master의 것을 상속하고 필요할 때만 지정한다.
- 마스터는 **course 단위로 하나만** 고른다. 강의 `meta.ts`의 `master`(선택)로 지정하고 없으면 `default`.
- 도구 제공 마스터는 `src/masters/{id}/index.tsx`(폴더 이름이 id, `import.meta.glob`으로 자동 등록, `_` 시작 폴더는 등록 제외), 강의 전용 마스터는 `courses/{강의}/masters/{id}/index.tsx`.
- id 조회 순서는 ① 강의 전용 → ② 도구 제공이고, 둘 다 없으면 사용 가능한 마스터 목록과 함께 오류. 같은 id가 양쪽에 있으면 강의 전용이 우선.
- `extendMaster(...)`로 다른 마스터를 확장할 수 있다.
- `defineMaster`, `extendMaster` 등의 API는 layout의 모양과 함께 확정한다(ADR에서 미뤄 둠).

### 현재 코드의 상태 (확인한 것)
- `CourseMeta`는 `title`만 가진다(`src/types.ts`). `master` 필드가 없다.
- `Slide`는 `<div className="slide">{children}</div>`뿐이다(`src/elements/index.tsx`). 마스터나 layout이 끼어들 자리가 없다.
- 슬라이드 미리보기 영역은 `Component`를 `SlidePreviewArea` 안에서 그대로 렌더링한다(`src/preview/App.tsx`). 마스터로 감싸는 단계가 없다.
- `.slide`의 배경은 `SlidePreviewArea`의 `.slide-preview-area-slide`가 `--color-slide-bg`로 칠한다. 즉 배경이 마스터가 아니라 미리보기 영역 쪽 CSS에 있다. export에는 이 영역이 없으므로 마스터 구현 때 배경의 소유 위치를 옮겨야 한다.
- `src/masters/`, `courses/*/masters/`는 없다. 샘플 강의 2개에도 `master` 지정이 없다.

### 결정 (이번 작업에서 정함)
- **이번 구현 범위에 포함한다**: ① `CourseMeta.master`(선택) 추가, ② 마스터 등록과 조회(`src/masters/`, `courses/*/masters/`, 조회 순서, 존재하지 않는 id의 오류), ③ `default` 마스터 추가. 상세 방식은 아래 미결 2~3과 함께 정한다.
- **마스터 안에 layout이 있다.** 예: 대제목, 목차, 컨텐츠, 제목만 있는 컨텐츠. 따라서 layout은 이번 범위에서 제외하지 않는다(앞서 "제외" 제안은 철회). layout의 이름, 슬롯 구조, 첫 구현에 넣을 layout의 수는 미결이다.
- **Tailwind 같은 utility class 방식은 채택하지 않는다.** 요소마다 클래스로 디자인을 제어하면 디자인이 마스터 한곳에서 정의된다는 마스터의 형식이 깨진다. 디자인은 마스터가 정의하는 값(테마 토큰, 배경, 요소 모양)으로 둔다.
- **layout은 슬라이드 크기(1920×1080)의 컨테이너이고, 슬롯은 그 안에 절대 위치로 놓는다. 좌표 단위는 px로 한다.** 슬라이드 크기가 모든 출력에서 고정이라 비율 좌표의 이점이 없고, 글자 크기와 여백이 px라 단위가 섞이는 것을 피한다. 미리보기의 확대 축소는 슬라이드 전체에 `transform: scale`을 적용하는 방식이라 px 좌표와 문제가 없다. 단, PPTX 추출(`getClientRects()`)은 배율 1인 export 모드에서 해야 한다.
- **layout마다 `background`를 다르게 지정할 수 있고, 지정하지 않으면 부모(master)의 `background`를 상속한다.** ADR [261007_002] ADR-1의 결정을 이번 구현에서도 따른다. 대체 방식은 아래 "배경 상속" 항목을 따른다.
- **`background`는 색 하나가 아니다.** 색, 이미지가 될 수 있고 svg, png가 함께 배치될 수도 있다. 따라서 `background`는 겹쳐 쌓는 여러 층(layer)의 구성으로 표현해야 한다. 층의 종류(색, 이미지, svg), 층마다의 위치와 크기(px), 이미지 파일을 두는 위치는 미결이다(이미지는 마스터 폴더 안에 두고 상대 경로로 참조하는 안). PPTX export에서 svg를 어떻게 다룰지는 확인하지 못했다.
- **쌓는 단계는 background(맨 아래) < layout < element(맨 위)로 고정이고, 한 단계의 요소는 다른 단계를 넘지 못한다.** 각 단계 컨테이너가 자기 쌓임 맥락(stacking context)을 가지게 해서 구현한다(예: 단계마다 `position: absolute; inset: 0; isolation: isolate`와 고정된 `z-index`). PPTX export에서는 단계 순서 → 단계 안의 순서로 도형 순서를 정한다.
- **단계 안의 쌓는 순서는 배열 순서로 정하고, `z-index` 숫자는 소스에 쓰지 않는다.** 렌더링할 때 배열에서 `z-index`를 만든다(`index × 100`). 모든 층, 슬롯, 요소에는 안정적인 `id`를 둔다. (앞서 "정수 `z-index`, 단계 안에서 고유, 100 단위"로 확정했던 것을 이 항목이 대체한다. 이유: 이후 화면 편집을 붙일 때 숫자는 간격 소진과 재번호 문제가 있고, 배열 순서와 `id`는 이동 연산 한 번으로 표현된다.)
- **단계에 들어가는 것(확정)**: 로고처럼 master 전체에 반영되는 것은 `background`, 특정 layout에만 반영되는 것은 `layout` 단계에 둔다. 구분선, 슬롯 테두리 등은 `layout` 단계이다.
- **배경 상속(확정)**: layout의 `background`는 master의 `background` 층 배열을 상속하고, **`id`로 그 부분만 대체**한다. 상속과 대체 규칙은 `background`에만 적용한다(`layout`은 부모 layout이 없으므로 대상이 아니다).
  - 아무것도 지정하지 않으면 master의 `background`를 그대로 쓴다.
  - master와 **같은 `id`**의 층은 그 자리에서 대체한다(순서는 master 것을 따른다).
  - master에 없는 `id`의 층은 새 층이며 master의 층 위에 자기 선언 순서대로 쌓는다.
  - `{ id: "logo", remove: true }`처럼 표시하면 master의 층을 뺀다.
  - 존재하지 않는 `id`를 대상으로 하는 `remove`는 오류로 알린다.
- **앵커(`above` 등)는 이번에 만들지 않는다.** 필요한 경우는 master에 없는 새 층을 master의 층 **사이**에 끼우는 것뿐이고, 실제로 필요해지면 추가한다(앵커가 없을 때의 기본 동작이 그대로라 나중에 추가해도 기존 소스가 깨지지 않는다).
- **화면 편집(나중, 미구현)**: 화면에서 고친 내용은 임시 JSON에 연산 기록으로 쌓는다(예: `{ op: "move", id: "corner", above: "pattern" }`). 확정되면 결정론적 도구나 agent가 소스를 바꾼다. 데이터로 선언된 값(좌표, 순서, 배경 층)은 도구가 기계적으로 고치고, 복잡한 변경에만 agent를 쓰는 안을 검토했다. 이 구상은 ADR [261007_003] ADR-1("화면에서 직접 고쳐 TSX에 저장하는 기능은 만들지 않는다")을 바꾸므로, 실제로 만들 때 새 ADR로 대체 관계를 남긴다. 지금은 모든 항목에 `id`를 두는 것만 이번 구현에 반영한다.
- 슬라이드의 요소(element 단계)는 작성 순서대로 쌓는다.
- 슬롯의 표현은 `x, y, w, h`(px)와 `type`(`title`, `subtitle`, `body`, `free` 등)을 가진 데이터로 선언하는 안을 검토 중이다(미확정). 슬라이드의 요소를 슬롯에 넣는 방식은 요소 종류로 자동 매핑하고 모호할 때만 `slot` prop으로 지정하는 혼합안을 제안했으나 확정하지 않았다. 슬롯 안 내용이 넘칠 때의 처리, 한 슬롯에 요소가 여러 개일 때의 간격도 미결이다.
- **마스터 적용 방식(확정)**: 마스터는 슬라이드를 그리는 공통 경로에서 적용한다(미리보기 전용이 아니다). export에도 같은 마스터가 적용되어야 하기 때문이다.
  - 공용 `MasterFrame`(`src/masters/MasterFrame.tsx`)이 해석된 마스터를 prop으로 받아 context로 내려 주고, 슬라이드 크기의 컨테이너(`.slide`, `data-master`)를 그린다. 미리보기와 export가 같은 `MasterFrame`을 쓴다. 마스터 밖에서 `Slide`를 그리면 오류로 알린다.
  - 마스터는 `resolveMaster(course.master)`로 찾는다(`course.master ?? "default"`, 조회 순서 ① 강의 전용 → ② 도구 제공, 없으면 사용 가능한 목록과 함께 오류).
  - `Slide`는 `layout` prop(선택)으로 layout을 고르고, background, layout(장식), element 세 단계(`Tier`)를 각각 그린다. 각 단계는 `position: absolute; inset: 0; isolation: isolate`이다. `layout`이 마스터에 없으면 사용 가능한 layout 목록과 함께 오류로 알린다.
  - `Title` 같은 요소는 context에서 자기 종류의 슬롯을 찾아 슬롯의 `x, y, w, h`로 절대 위치에 놓는다.
  - 슬라이드 파일은 바꾸지 않는다. `layout`을 생략하면 기본 layout(컨텐츠 계열)으로 그린다. 기본값의 이름은 구현할 때 정한다.

### 결정 (마스터 구조)
- **마스터의 형태**: `index.tsx`는 `defineMaster({...})`가 만든 **객체**를 내보낸다. layout, 슬롯, 배경 층, 상속이 모두 데이터로 선언되어 PPTX 변환과 이후의 도구 수정에 유리하다.
- **슬롯**: `{ id, type, x, y, w, h }`(px). `type`은 `title`, `subtitle`, `body`, `free` 등이다. 슬라이드의 요소는 종류로 자동 매핑하고(`Title` → `title`, `Bullets`/`Paragraph` → `body` 또는 `free`), 모호할 때만 `slot` prop으로 지정한다. 기존 PPTX는 77장 중 67장이 "제목만 있는 컨텐츠"라 `free` 슬롯을 일급으로 둔다.
- **디자인의 소유**: 슬라이드 디자인(테마 토큰, 배경, 요소 모양)은 `styles.css`가 아니라 **마스터**가 가진다. 마스터의 값은 CSS 변수로 노출하고 `[data-master]`로 범위를 한정하며, 요소는 변수만 읽는다. `@font-face`, 미리보기 UI, 슬라이드의 구조(크기 100%)는 도구에 둔다. 지금 `.slide-preview-area-slide`가 칠하는 배경은 마스터의 `background` 층으로 옮긴다.
- **배경 층의 필드**: `{ id, type: "color" | "image" | "shape", ... }`. `image`는 `{ src, x, y, w, h }`(px), `shape`는 `{ path, viewBox, fill, shadow, x, y, w, h }`로 두어 PPTX의 자유형 값을 그대로 옮길 수 있게 한다. 이미지는 마스터 폴더의 `assets/`에 두고 상대 경로로 가져온다.
- **슬롯 넘침과 간격**: 내용이 슬롯을 넘쳐도 그대로 두고 경고만 한다(PPT와 같음). 한 슬롯에 요소가 여럿이면 세로로 쌓고 간격은 마스터의 토큰으로 정한다.
- **슬라이드의 자유 배치 요소를 이번 범위에 포함한다.** 기존 PPTX가 77장 중 67장을 "제목만 있는 컨텐츠"에 본문을 직접 놓아 만들었고, 지금 설계(슬롯 안 요소는 세로로 쌓임)로는 이런 슬라이드를 만들 수 없기 때문이다.
  - `Text`, `Shape`, `Image` 요소를 추가하고, 선택적인 `at={{ x, y, w, h }}`(슬라이드 기준 px, 마스터와 같은 좌표 규칙)을 받는다. `at`이 없으면 슬롯에 자동으로 들어가고(기존 방식), 있으면 절대 위치에 놓는다.
  - 쌓는 순서는 작성 순서이다(element 단계 안).
  - 문구는 슬라이드 맨 위 `text` 객체에 모으는 규칙을 유지하고, 좌표는 JSX의 `at`에 선언한다(선언이므로 "로직을 넣지 않는다"와 충돌하지 않는다).
  - **이번에 하지 않는 것**: `Group`(그룹 기준 상대 좌표, 도형과 그 위의 문구를 함께 옮기는 용도), `Row`/`Column` 같은 자동 배치, 표. 필요해지면 추가한다.
  - 미결: `Shape`의 종류(사각형, 둥근 사각형, 자유형 경로 등)와 속성(채움, 선, 그림자), `Text`의 글자 속성(크기, 색, 정렬, 굵게), 슬라이드의 이미지 파일을 두는 위치(강의 폴더의 `assets/` 등), 마스터 `shape` 층과 슬라이드 `Shape`의 속성을 같게 쓸지.
  - 이 항목으로 이번 브랜치의 범위가 마스터와 layout에서 요소 추가까지 넓어졌다. 구현은 마스터(`MasterFrame`, layout)가 먼저이고 자유 배치 요소는 그 위에 얹는다.
- **`PromptBox` 요소를 추가한다(마스터가 모양을 정한다).** 기존 PPTX의 슬라이드 17, 60, 66번에 있는 프롬프트 박스를 요소 하나로 쓰기 위해서다. `Group`은 이번에 만들지 않는다(앞선 결정 유지).
  - 기존 PPTX의 박스는 그룹 하나이며, 그룹 안 상대 좌표는 다음과 같다(슬라이드 17번 첫 박스, 399×171px 기준). 바탕은 둥근 사각형(채움 `#0C0C0C`, 테두리 `#D77757` 3px, 모서리 반지름 약 5px), 구분선은 x35 y74 길이 328 흰색 3px, 아이콘은 x167 y20 w64 h43, 문구는 x30 y79 w334 h74(나눔스퀘어, 색은 테마 `accent4` = `#FFC000`). 60번(559×281), 66번(559×388)은 같은 모양에 크기만 다르다.
  - 사용 형태: `<PromptBox at={{ x, y, w, h }} value={text.prompt} />`. 문구는 다른 요소처럼 `text` 객체에 둔다.
  - 모양(바탕, 테두리, 구분선, 아이콘, 글자 색)은 슬라이드가 아니라 **마스터의 디자인**이 정한다. 박스 크기가 달라져도 안쪽 배치(구분선 위치, 아이콘 위치, 문구 영역)는 박스 크기를 기준으로 계산한다.
  - PPTX export에서는 이 요소를 도형, 선, 그림, 글상자로 이루어진 그룹으로 풀어서 내보내, 받은 사람이 편집할 수 있게 한다.
  - 미결: 마스터가 요소의 디자인을 어떻게 선언하는지(`defineMaster`의 `elements` 같은 항목인지, CSS 변수만으로 하는지), 박스 크기에 따른 안쪽 배치 규칙(고정 여백인지 비율인지), 아이콘 이미지(기존 PPTX의 아이콘은 복사하지 않았다), 색을 마스터의 팔레트와 분리해서 정의하는 방법, 프롬프트 문구가 여러 줄일 때의 처리.
- **`Chip` 요소를 추가하고, 강의에서만 쓰는 변형은 강의의 `elements/`에 둔다.** `PPT 도형.pptx`(슬라이드 1장에 도형 약 60개)를 분석한 결과다.
  - 도구가 제공하는 것은 **`Chip` 하나**이다. 둥근 사각형 안에 아이콘과 글자를 넣는 요소이며, 폭은 글자에 맞춰 자동으로 계산한다. 아이콘은 이미지 경로(`icon`)를 받는 일반적인 속성이다. 모양(높이 74px, 채움 `#F2F2F2` = 흰색 95%, 흰 테두리 1.5pt, 반지름 약 12px, 글자 36px 추정)은 마스터가 정한다.
  - **도구에 아이콘을 넣지 않는다.** 이 PPTX의 주황 캐릭터, 터미널, 파일, VS Code 아이콘은 모두 특정 강의(Agent 강의)에서 쓰는 변형이라 그 강의의 폴더에서 가진다. 제3자 이미지일 수 있어 이 저장소에 복사하지 않았다.
  - **강의 전용 요소**: `courses/{강의}/elements/`에 그 강의에서만 쓰는 요소를 둔다. `masters/`와 같은 방식(도구 저장소를 건드리지 않고 강의 저장소 안에서 확장)이다. 이 PPTX에서 변형되는 것들이 여기에 들어간다: 아이콘별 칩(`claude`, `terminal`, `file`, `vscode`), 단계 번호(빨간 원), 강조 테두리, 설명 캡션, 도장("완료"), 점선 박스, 각주 등. 도구의 `Chip`, `Shape`, `Text`를 조합해서 만든다.
  - 이 PPTX의 나머지 유형(화살표, 번호 원, 강조 테두리, 도장, 배너, 점선 박스)은 새 도구 요소를 만들지 않고 `Shape`/`Text`의 속성으로 표현한다.
  - 이 PPTX의 색(빨강 `#FF0000`, 하늘색 `#00B0F0`, `accent4` = `#FFC000`)은 마스터의 팔레트(`#164194` 계열)와 다른 "표시용 색"이라 강의 전용 요소가 가진다.
  - 이 저장소에는 Agent 강의가 없다(`courses/`에서 추적하는 것은 `sample`, `sample2`뿐). 위 요소들은 그 강의 저장소를 만들 때 그 안에 둔다. 지금은 구조만 정한다.
  - 미결: 슬라이드가 강의 전용 요소를 가져오는 경로(상대 경로, 별칭 등), 도구의 요소와 이름이 같을 때의 규칙, 강의 전용 요소가 마스터의 CSS 변수를 읽을 수 있는지(읽게 하는 안), README와 CLAUDE.md의 구조도에 `courses/{강의}/elements/`를 반영하는 시점.
  - **`PromptBox`는 도구 요소로 둔다(확정).** 기본값은 기존 PPTX의 현재 값이다(바탕 `#0C0C0C`, 테두리 `#D77757` 3px, 구분선 흰색 3px, 글자 `#FFC000`). 아이콘은 선택 속성이고 도구는 아이콘 이미지를 제공하지 않는다. 색과 아이콘을 바꾼 **변형은 강의의 `elements/`에 만든다**(예: Agent 강의의 주황 캐릭터 아이콘을 쓴 `PromptBox` 변형). 변형은 도구의 `PromptBox`를 조합해서 만든다.
- **마스터 선택 드롭다운은 이번에 넣지 않는다.** 마스터가 `default` 하나뿐이다. 둘 이상이 되면 넣는다.
- **로고는 기본으로 넣는다.** default 마스터의 대제목 layout에 포함한다.
- **PPTX export는 진짜 PPTX 슬라이드 마스터로 만든다.** 마스터는 PPTX의 슬라이드 마스터로, layout은 슬라이드 레이아웃으로, 슬롯은 플레이스홀더로, 배경 층과 장식은 마스터와 layout의 도형으로 내보낸다. 받은 사람이 PowerPoint에서 편집하기 쉽게 하기 위해서다. 영향과 남은 문제:
  - 슬롯의 `type`은 PPTX 플레이스홀더 종류(title, subTitle, body 등)에 대응해야 한다. `free`는 플레이스홀더로 만들지 않는 슬롯으로 둘 수 있다.
  - ADR [261007_001] ADR-4는 슬라이드 본문을 줄마다 텍스트박스로, 자동 줄바꿈을 끄고 내보내기로 정했다. 플레이스홀더에 들어가는 글은 PowerPoint가 줄바꿈을 다시 하므로, 슬라이드의 본문 텍스트를 어떻게 내보낼지(편집 용이성과 모양의 일치 사이) 다시 정해야 한다.
  - 자유형 도형과 바깥 그림자를 PPTX의 도형 속성으로 쓸 수 있는지 확인하지 못했다(ADR-4는 복잡한 그림자를 이미지로 두기로 했다).
  - 이전 노트의 "진짜 마스터로 올릴지, 슬라이드마다 복제할지"는 이 결정으로 **올린다**로 정해졌다.
- **날짜, 바닥글, 슬라이드 번호 슬롯은 이번에 넣지 않는다.** 나중에 한다.
- **목차 layout의 항목 슬롯**: PPTX는 번호와 내용 슬롯 10쌍을 따로 놓았다. 반복되는 줄을 슬롯 하나(줄 간격을 가진 목록)로 표현할지 쌍마다 선언할지는 미결이다.
- **목차의 고정 문구와 항목 슬롯(확정)**: 고정 문구는 배경 층의 새 종류 `text`(`{ value, x, y, w, h, size, color, align }`)로, 항목 10줄은 `list` 슬롯 하나(`rows`, 균일한 `pitch`, `columns`)로 표현한다. 슬라이드에서는 목차 요소가 항목 배열로 채우고, PPTX export에서는 줄 수만큼 플레이스홀더로 푼다. 기존 PPTX의 줄 간격(73~80px)은 균일한 `pitch`로 단순화한다.
- **PPTX 본문 텍스트(확정)**: 문단마다 텍스트박스 하나로, 자동 줄바꿈을 켜서 내보낸다(ADR [261007_001] ADR-4의 줄 단위 방식을 이 부분에서 대체). 줄바꿈이 HTML과 얼마나 달라지는지는 export 구현 때 PowerPoint와 비교해 확인한다. 인라인 `badge()`/`code()`가 있는 문단의 내보내기 방식은 미결이다.
- **`Shape`/`Text`의 속성(확정)**: `Shape`는 `kind`(`rect`, `roundRect`, `ellipse`, `rightArrow`, `triangle`, `line`, 자유형 `path`), `radius`, `fill`(색, 없음, 투명도), `line`(색, 굵기, 실선/점선), `rotate`, `shadow`, `text`. `Text`는 `size`, `color`, `align`, `anchor`, `bold`, 바탕 `fill`, 줄 간격. 색은 직접 값과 마스터 토큰 이름을 둘 다 받는다.
- **강의 전용 요소를 가져오는 경로(확정)**: 슬라이드는 상대 경로(`../../../elements`, 깊이가 고정)로 가져오고, 강의의 `elements/index.ts`는 `export * from "@/elements"`로 도구 요소를 다시 내보내며 같은 이름이면 강의 것이 우선한다. 이 동작은 시험하지 않았다.
- **section의 표시 이름은 강의마다 정한다(확정).** 강의 `meta.ts`(`CourseMeta`)에 section을 부르는 이름(예: `SECTION`, `UNIT`, `MODULE`)을 정하는 선택 필드를 둔다. 필드 이름은 `sectionLabel`(구현 때 확정). 기본값은 `SECTION`이다. 목차, 미리보기의 사이드바, 상단 바(breadcrumb)가 이 값을 쓴다(표시 형식은 구현 때).
- **목차는 section 제목으로 자동으로 채운다(확정)**: 목차 요소가 현재 슬라이드가 속한 chapter의 section 목록(`meta.ts`의 `title`)에서 항목을 만든다. 번호는 section 순서, 이름 앞에 `sectionLabel`을 붙일 수 있다. `MasterFrame`이 chapter 정보를 context로 내려 준다. section이 `list` 슬롯의 `rows`(10)보다 많으면 넘치는 항목은 표시하지 않고 경고한다. 항목을 직접 지정하는 방식(`items`)은 두지 않는다. 자동으로만 채운다(확정).

### 결정 (default 마스터)
- **색은 이 PPTX의 값을 가져온다.** 주색 `#164194`(제목, 띠, 번호), 진한 주색 `#204273`(오른쪽 아래 도형), 연한 회색 `#E7E6E6`(목차 패널). 이에 따라 default 마스터의 모습이 현재 `styles.css`의 값(`#1f4e79`)과 달라지므로, 기존 샘플 17장의 모습이 바뀐다. 샘플이 "같은 모습"이어야 한다는 앞선 확인 항목은 이 결정으로 바뀐 모습으로 확인한다.
- **default의 layout은 4개로 시작한다.** 대제목, 목차, 컨텐츠(제목 및 내용), 제목만 있는 컨텐츠. 챕터 슬라이드 layout은 이번에 넣지 않는다.
- **장식 도형과 로고를 모두 가져온다.** 위 "장식 도형의 형태"의 값을 쓴다. 로고 파일은 `src/masters/default/assets/logo.svg`, `logo.png`에 복사했다(스크립트와 외부 참조가 없음을 확인함). 그림자는 ADR-4에 따라 PPTX export에서 처리 방식을 정한다(미결).
