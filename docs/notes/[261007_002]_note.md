- **`NanumSquare_ac` 계열은 사용하지 않으므로** 정확한 의미는 알 필요가 없다. (미결에서 제외)

- **PDF 생성 방식은 HTML을 실제로 인쇄해 보고 결정**한다. (결정 시점: 프로토타입 이후)

### 논의(진행 중): 프로젝트 구조와 용어
- 원칙: PPTX에서 쓰는 용어나 개념적으로 쓰는 용어와 헷갈리면 안 된다.
- 계층:
  - `course`: 하나의 전체 강의 (최상단 카테고리)
  - `chapter`(가칭): 실제 파일로 배포하는 단위. 이름 미확정.
  - `section`: 수업 주제 단위. 하나의 `chapter`는 여러 `section`을 가진다. **PowerPoint의 구역(Section)과 같은 개념**(결정).
  - `slide`
  - `element`: slide 아래의 구성요소. `group`으로 여러 element를 묶을 수 있다. (기존 `component`/`unit`을 대체. React component와의 혼동을 피하기 위해 `component`라는 계층 용어는 쓰지 않는다.)
- 용어 결정:
  - `component`는 계층 용어로 쓰지 않는다. **`block`은 도입하지 않고 뺀다**(결정).
  - `unit` → **`element`**: 구성요소라는 의미. **`element`는 `group`도 가능**(group 안에 element를 묶을 수 있음).
  - `slide-master`: **PowerPoint의 슬라이드 마스터와 같은 개념**(의도적 1:1 대응).
  - `section`: PowerPoint 구역과 같은 개념.
- `slide-master`의 구성(결정):
  - `slide-master` 안에 **`background`와 `layout`**이 들어 있다.
  - **`layout`마다 `background`를 가진다.** 기본은 master(layout)의 background를 **상속**하고, 필요하면 layout에서 `background`를 지정(override).
- 정의: `slide-master`=모든 슬라이드에 반복되는 공통 요소(로고, 페이지 번호, 푸터)와 기본 background, `layout`=영역 배치 틀(제목+본문, 2단 등), `element`=내용을 담는 구성요소(제목, 불릿, 그림, 표, 뱃지 등), `group`=여러 element를 묶은 것.
- 용어 충돌 후보(남은 것):
  - `element` ↔ DOM element, XML element. DOM 추출 코드와 PPTX XML을 다루는 곳에서 혼동 가능 → 코드/문서에서 DOM 쪽은 `DOM element`로 표기하는 규칙 권고.
  - `group` ↔ PPT 그룹 도형(같은 개념으로 1:1 대응 가능), SVG `<g>`.
  - `section` ↔ HTML `<section>` 태그(코드에서 구분 필요).
  - `layout`이 PPT 슬라이드 레이아웃과 같은 개념인지, PPTX 생성 때 진짜 마스터/레이아웃을 쓸지는 미정.
- 정리: 기존에 네 가지(background/slide-master/layout/unit)를 `component`로 묶었으나 `slide-master`가 `background`와 `layout`을 포함하게 되어 같은 층위가 아니므로, **통칭하는 상위 용어(`block`)는 두지 않는다.** 구조는 `course → chapter → section → slide → element(group)`과, 별도로 `slide-master → background, layout(background)`로 구성한다.
- **결정: PPTX 고유 개념은 필요할 때 `pptx` 접두사를, DOM 고유 개념은 `dom` 접두사를 붙여 구분한다**(예: `pptx layout`, `pptx master`, `dom element`). 접두사 없는 용어는 우리 구조의 용어로 읽는다. 이 결정으로 `element` ↔ DOM element/XML element 충돌은 해소됨.
- 제안: 용어 확정 후 `docs/glossary.md`에 정의를 모아 ADR/코드에서 같은 이름 사용.

### 논의: 미리보기 프레임워크
- 제안: **Vite + React + TypeScript**. TSX를 바로 실행하고 HMR로 슬라이드 저장 즉시 갱신. `import.meta.glob`으로 `slides/*.tsx`를 모아 `deck.ts` 순서대로 표시.
- 같은 앱이 세 역할을 함: (1) 개발 중 미리보기(dev 서버), (2) Playwright가 위치 추출과 PDF 인쇄를 하는 대상, (3) `vite build`로 만든 정적 사이트 = 최종 HTML 강의자료. 미리보기와 결과가 달라지는 문제가 없음.
- 미리보기 화면 요구: 1920×1080 고정 스테이지를 `transform: scale()`로 창에 맞춤, 슬라이드 목록(section별)과 이동, `?export` 같은 모드에서 스케일 없이 원본 크기로 한 장씩 렌더링(Playwright용), `assets/fonts/`의 NanumSquare를 `@font-face`로 로드.
- 대안: Next.js(과함), Storybook(element 단위 확인용으로 나중에 추가 가능), Astro(이점 적음).
- ADR-4의 "React SSR" 표현은 조정 필요: Vite를 쓰면 브라우저 렌더링 결과를 Playwright가 읽는 방식이 더 단순함.
- 상태: **Vite + React + TypeScript 채택**(사용자 확정).
- **결정: 최종 HTML은 단일 HTML 파일로 export한다.** **`chapter`를 파일 단위로 지정**한다(chapter 하나 = 배포 파일 하나 = 단일 HTML 하나).
- **결정: 폰트는 R(Regular), B(Bold)만 사용한다.** `L`(Light)과 `EB`(ExtraBold)는 쓰지 않는다. → ADR-5의 4종 사용과 `fonts` 토큰 예시(`heading: NanumSquareEB`, `caption: NanumSquareL`)를 대체함. 테마 토큰은 R/B 두 가지로 다시 매핑해야 함(제목과 강조는 B, 본문과 캡션은 R 등). 폰트가 2종이라 단일 HTML 용량도 줄어듦(base64 기준 약 2MB 안팎 예상).
- 단일 HTML 빌드: `vite build` 기본 결과는 `index.html` + JS/CSS/폰트/이미지의 여러 파일이라 단일 파일이 아님. `vite-plugin-singlefile`로 JS/CSS를 HTML에 인라인하고 이미지/폰트는 base64로 넣어 단일 HTML로 만들 수 있음(플러그인이 바꾸는 옵션은 프로토타입에서 빌드해 확인).
  - 용량: NanumSquare 4종(각 약 700KB)을 base64로 넣으면 약 4MB 증가 → 실제 쓰는 한글 글자만 남기는 폰트 서브셋 또는 쓰는 굵기만 포함.
  - `file://`로 직접 열려면 해시 라우팅(`#/s2`) 필요. 경로 방식(`/s2`)은 동작하지 않음.
  - 빌드 단위: `chapter`가 배포 파일 단위이므로 **chapter 하나 = 단일 HTML 하나**가 되도록 chapter별로 빌드(빌드 때 포함할 chapter를 지정하는 방식 필요).

### 결정: 폴더 구조, AI 연동 방식, 범위
- 폴더 구조: `courses/{강의명}/ch.N_{chapter명}/sec.N_{section명}/sl.N_{slide명}/index.tsx`.
  - `section`은 폴더이면서 `meta.ts`를 가진다. course, chapter 폴더에도 `meta.ts`(title)를 둔다.
  - `slide`는 폴더별로 관리하고, section `meta.ts`의 `slides` 배열에도 포함한다(슬라이드 순서의 기준은 이 배열).
  - chapter/section의 순서는 폴더 이름의 번호(`N`)로 정한다.
  - slide 폴더 이름 규칙 `sl.N_이름`은 에이전트가 정한 가정(사용자 확인 필요).
- AI 연동: **지금은 Claude Code 같은 도구를 켜 두고 TSX 수정을 시키는 로컬 방식**, 미리보기는 React로 한다. 서비스이지만 TSX는 아직 로컬에서 수정하고, **나중에 agent를 연동**한다.
- 범위: **일단 미리보기 창 수준**까지만 만든다.
- `layout` 종류는 **나중에 정한다**.
- 시각 비교 테스트(HTML ↔ PPTX)는 **나중에 PPTX로 export할 때** 시행한다.
- 폰트 라이선스: 프리(무료).
- `.gitignore`: `node_modules/`, `dist/`, `.vite/`, `*.tsbuildinfo`, `*.log`, `.env*`(`.env.example` 제외), `coverage/`, OS 파일(`desktop.ini`, `Thumbs.db`, `.DS_Store`) 추가.

### 작업 현황: 미리보기 앱 (Vite + React + TypeScript)
- 구성: `package.json`, `vite.config.ts`(`@` → `src` 별칭), `tsconfig.json`, `index.html`, `src/`, `courses/`.
- `src/courses.ts`: `import.meta.glob`으로 `courses/` 아래 `meta.ts`와 `index.tsx`를 읽어 course → chapter → section → slide 트리를 만든다. meta에는 있는데 폴더가 없거나, 폴더는 있는데 meta에 없으면 콘솔 경고.
- `src/preview/`: 사이드바(트리), 스테이지(1920×1080을 창에 맞춰 축소), 이전/다음 버튼과 방향키 이동, 해시 라우팅(`#/강의/chapter/section/slide`).
  - 사이드바 접기/펼치기: 상단 바의 ☰ 버튼. 상태는 `localStorage`(`preview.sidebarOpen`)에 저장하며, 저장소를 못 쓰는 환경에서도 동작하도록 예외를 무시한다.
  - 상단 네비게이션 바(`TopBar`): 사이드바 토글, 현재 위치(course / chapter / section / slide) 표시, 오른쪽 `children` 영역에 항목(버튼 등)을 추가할 수 있다.
- `src/elements/`: `Slide`, `Title`, `Paragraph`, `Bullets`와 인라인 서식(`badge`, `bold`, `code`) — ADR-3의 세그먼트 배열 방식.
- 폰트: `assets/fonts`의 R(400), B(700)을 `@font-face`로 연결(가짜 굵게 방지). 테마 값은 `:root` CSS 변수.
- 샘플: `courses/sample/ch.1_intro/` (section 2개, slide 4장).
- 검증: `npm run build`(타입 검사 + 빌드) 통과. 개발 서버는 `npm run dev`로 `http://localhost:5173/`에서 응답(HTTP 200)을 확인함. **브라우저에서 실제 화면은 아직 확인하지 못함**(연결된 Chrome에서 localhost 접속 오류).
- TypeScript 7에서는 `baseUrl` 옵션이 제거되어 `paths`만 사용(`"@/*": ["./src/*"]`).
- 아직 안 한 것: 단일 HTML export(`vite-plugin-singlefile`), 슬라이드 마스터/레이아웃, `?export` 모드, Playwright 추출, PPTX/PDF export.

### 논의: export 범위
- PPTX와 PDF는 **슬라이드 스테이지(1920×1080)만** 대상이다. 미리보기 창의 사이드바, 상단 바, 이전/다음 컨트롤은 포함하지 않는다. (미리보기 앱은 뷰어일 뿐이고, export는 스테이지 요소만 읽거나 인쇄하도록 `?export` 모드를 둘 예정)
- 단일 HTML export에 **뷰어(슬라이드 이동 UI)를 포함할지는 미결**. 슬라이드만 있으면 한 장씩 넘겨 볼 수 없으므로, 최소한의 뷰어(스테이지 축소 표시, 이전/다음, 방향키)를 포함하는 방향을 제안함. 미리보기 전용 UI(개발용 상단 바 항목 등)는 제외.
- PPTX/PDF의 출력 단위(chapter별 파일 등)는 미정.
