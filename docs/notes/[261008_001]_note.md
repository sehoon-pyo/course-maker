### 작업 현황
- 마스터 구현 1~5단계를 끝내고 커밋함(`f03c786`, `3b54c25`, `21d3d32`, `220d1ce`, `f920ed6`). 계획과 결과는 [`docs/plan.md`](../plan.md)에 있다.
- 5단계(`sectionLabel` 적용)에서 화면의 `SECTION n`이 폴더 번호가 아니라 **chapter 안의 순서**에서 나온다는 점이 드러났고, 순서를 정하는 규칙을 다시 따졌다.

### 논의: 순서를 폴더 번호로 정하는 방식
- 지금(ADR [261007_002] ADR-2): **slide는 section `meta.ts`의 `slides` 배열**이, **chapter와 section은 폴더 이름의 번호(`ch.N_`, `sec.N_`)**가 순서를 정한다.
- 문제
  - 번호가 폴더 이름에 박혀 있어, section을 끼워 넣으면 뒤의 폴더 이름을 모두 바꿔야 하고 git에서는 폴더 이동 diff가 크다. slide를 배열로 바꾼 이유와 같다.
  - 규칙이 둘이다(slide는 배열, chapter와 section은 번호). 번호가 겹치거나 빠지면 순서가 파일을 찾은 순서(경로의 글자 순)로 우연히 정해진다. 두 폴더가 모두 번호가 없으면 비교 결과가 `NaN`이 되어 정렬이 정의되지 않는다.
  - 화면에 보이는 번호(`SECTION n`)는 이미 순서에서 나온 값이라 폴더 번호와 달라질 수 있다.

### 결정
- **순서는 course → chapter → section → slide 모두 상위 `meta.ts`의 배열이 정한다.** 강의 `meta.ts`의 `chapters`, chapter `meta.ts`의 `sections`, section `meta.ts`의 `slides`. 폴더 이름의 번호는 순서의 기준이 아니다.
- **폴더 이름의 번호 접두사는 선택이다.** `ch.1_intro`, `sec.1_variable`, `sl.1_title`처럼 번호를 붙여도 되고, `ch.intro`, `sec.variable`처럼 번호 없이 써도 된다. 번호는 정리용이며 배열과 어긋나도 화면 순서에는 영향이 없다. 화면에 보이는 이름은 접두사(`ch.`, 번호와 `_`)를 뗀 부분이다.
- **배열과 폴더가 어긋나면** slide와 같이 콘솔에 경고한다. 배열에 있는데 폴더가 없는 항목은 건너뛰고, 폴더는 있는데 배열에 없는 항목은 표시하지 않는다. 배열에 같은 이름이 둘이면 첫 번째만 쓰고 경고한다.
- **숨김 슬라이드를 둔다.** section `meta.ts`의 `slides` 항목을 문자열 대신 `{ id: "sl.3_extra", hidden: true }`로 쓰면 숨김이다. **뷰어(미리보기)에서는 숨김 슬라이드도 보이고**(사이드바에 "숨김" 표시, 현재 슬라이드가 숨김이면 하단에 안내), 이전/다음과 `n / 전체`에 포함된다. HTML, PPTX, PDF export에서는 제외한다(export는 아직 없다). PowerPoint의 숨기기 슬라이드와 같은 개념이다.
- 숨김의 표시 위치는 `slides` 항목이다(슬라이드 파일 안이 아니다). 순서와 같은 곳에서 한 번에 관리하기 위해서다. 별도의 `hidden` 배열은 두지 않는다.

### 구현 순서 (판단)

### 미결
- `ch.`, `sec.`, `sl.` 접두사를 아예 없앤 이름(`intro`처럼 점이 없는 이름)을 권장하는지. 현재 코드는 접두사가 없어도 읽는다.
- 숨김 슬라이드를 export에서 제외하는 구현은 export를 만들 때 한다.
- `hidden` 외의 슬라이드 속성(예: 발표자 메모)을 같은 객체 항목에 둘지.
