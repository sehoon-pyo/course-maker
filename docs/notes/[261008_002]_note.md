### 요청 3. 문장 안의 뱃지와 본문 글자의 가로 중앙선을 맞춘다
- 요청: 문장 안의 **뱃지**(`badge()`, 예: "본문 슬롯의 요소는 [세로]로 쌓인다"의 파란 알약)와 일반 텍스트의 **가로 중앙선**이 맞도록 한다. 지금은 뱃지가 중앙보다 조금 아래에 있는 것처럼 보인다. (처음에는 `Chip` 요소로 이해했으나 사용자가 보여 준 화면은 인라인 뱃지였다. 아래 "칩" 분석은 이 요청의 대상이 아니다.)
- 원인(화면에서 측정함, 본문 글자 48px, `sample/ch.3_master/sec.1_layouts/sl.3_content`)
  - 뱃지는 `display: inline-block`이고 기본으로 **기준선(baseline)에 앉는다**(`.badge`에 `vertical-align`이 없다). 뱃지 글자는 본문의 0.8배(38.4px)이고 줄 높이 1.5라서 박스 높이가 57.6px이다.
  - 본문 한글의 눈에 보이는 세로 중심은 기준선 위 **0.323em**(15.5px), 뱃지 박스의 중심은 기준선 위 **0.233em**(11.2px)이다. 즉 뱃지가 본문 글자의 중심선보다 **약 0.09em(4.3px) 아래**에 있다.
  - 뱃지 안의 글자는 알약의 가운데에 거의 맞는다(박스 중심과 글자 중심의 차이 0.8px). 그래서 문제는 뱃지 안이 아니라 **본문 줄에서의 위치**이다.
- 고치는 방향(제안, 구현 전): 뱃지를 본문 줄의 중심선 쪽으로 올린다. `.badge`에 `vertical-align`(위로 약 0.09em, 뱃지 글자 기준으로는 약 0.11em)을 준다. 값은 글자 크기에 비례하므로 em 단위로 정한다. 본문 글자가 달라져도(제목 76px 등) 같은 비율로 맞는다.
- 확인할 것
  - 같은 줄의 `code()`(인라인 코드)와 `bold()`는 기준선에 앉은 글자 그대로라 본문과 중심선이 같다(측정하지는 않았다). 뱃지만 박스가 커서 어긋난다.
  - 뱃지 색(`green`, `red`, `blue`, `gray`)과 상관없이 같은 위치 문제이다.
  - 글꼴의 지표(NanumSquare)에 의존하는 값이라 PowerPoint로 내보낼 때(뱃지를 도형으로 놓음, ADR [261007_001] ADR-4)의 위치는 따로 정해야 한다.
- (참고) `Chip` 요소를 `Text`와 같은 `y`에 `at`으로 놓으면 칩 높이(74px)와 글의 줄 높이가 달라 중심이 어긋날 수 있다(글자 36px이면 칩이 10px 아래). 사용자가 말한 것은 이것이 아니므로 이번 요청에서는 다루지 않는다.

### 요청 4. 아이콘이 빠진 칩과 프롬프트 박스에 claude 이미지를 넣는다
- 요청: 칩 중에 claude 이미지(주황 캐릭터)가 빠진 것에 넣는다. **프롬프트 박스의 아이콘도 같은 claude 이미지**이다.
- 확인한 것(`PPT 도형.pptx`): 프롬프트 박스 안에 있는 그림(박스 기준 x167.3 y19.7, 64×43.1)이 칩에 쓰인 것과 같은 파일 `image4.png`이다. Agent View 덱의 프롬프트 박스 아이콘(`image21.png`)과도 파일 내용이 같다(해시 일치, 943바이트, 204×192).
- 파일의 상태: `image4.png`는 PowerPoint의 "배경 제거"가 이미 적용된 결과라 **배경이 투명**하다(팔레트 PNG의 `tRNS` 청크로 확인). 배경을 지우기 전의 원본은 같은 그림에 딸린 `hdphoto1.wdp`(JPEG-XR)에 들어 있고, 그림의 원래 이름은 `slide12_img1.png`이다. 우리가 쓸 것은 배경이 지워진 `image4.png`이고, 원본(`hdphoto1.wdp`)은 필요 없다.
- 지금 샘플의 프롬프트 박스(`sl.3_promptbox`)는 PPTX의 아이콘 대신 이 저장소에서 직접 그린 별 모양(`courses/sample/assets/icon-spark.svg`)을 쓰고 있다. claude 이미지로 바꾸고, 그려 둔 별 아이콘은 쓸 곳이 없어지므로 지운다.
- **이미지는 잘라서 쓴다**: 모든 자리(칩 11개, 프롬프트 박스 1개, 그 밖 1개)가 원본의 **위쪽 16.753%, 아래쪽 11.651%를 잘라서**(PPTX의 `srcRect`) 쓴다. 원본에는 위아래에 빈 여백이 있다. 잘린 그림의 비율은 약 1.48:1(204×137.5)이고(사용자가 보여 준 67×46 이미지와 같은 비율), 칩에서는 56×37.7px, 프롬프트 박스에서는 64×43.1px로 놓인다. 여백을 자르지 않고 쓰면 캐릭터가 작아 보인다. 이미지 파일을 잘라서 저장하거나 CSS로 잘라서 보이는 안이 있다.
- 기준: 기존 PPTX(`PPT 도형.pptx`)의 칩 종류별 아이콘
  - claude 이미지: 슬래시 명령과 단축키(`/bg`, `/resume`, `/exit`, `ctrl + x`, `ctrl + t`, `ctrl + s`, `ctrl + r`, `←`, `?`)
  - 터미널 아이콘: `command`, `claude`, `claude agents`
  - 파일 아이콘: `CLAUDE.md`
  - VS Code 아이콘: ``ctrl + ` ``
- 지금 샘플의 칩
  - `courses/sample/ch.3_master/sec.2_elements/sl.2_chips`: `/bg`(아이콘 없음), `ctrl + x`(터미널 아이콘), `CLAUDE.md`(파일), `claude agents --verbose`(터미널)
  - `courses/sample/ch.3_master/sec.1_layouts/sl.4_flow`: `/resume`(아이콘 없음), `claude agents`(터미널)
  - 위 기준대로면 `/bg`, `/resume`, `ctrl + x`에 claude 이미지를 넣어야 한다. `ctrl + x`는 지금 터미널 아이콘이라 기준과 다르다.
- 이미지 파일: `PPT 도형.pptx`의 `image4.png`(204×192, 주황 캐릭터)를 샘플 강의의 `courses/sample/assets/`에 두는 안. 도구는 아이콘을 제공하지 않고 강의가 가진다는 결정(ADR [261007_004] ADR-8, 9)에 따라 도구의 `src/`가 아니라 강의의 `assets/`이다. 이 이미지는 제3자의 것일 수 있다는 점을 앞서 알렸고, 사용자가 넣으라고 한 것으로 이해한다.
- 같이 정할 것: 아이콘의 크기 규칙.
  - 기존 PPTX는 터미널, 파일 아이콘이 정사각형(56×56 안팎)이고 잘라 쓴 주황 캐릭터는 56×37.7이다. 지금 CSS는 칩 아이콘의 높이를 `--chip-icon-size`(56px)에 맞추고 폭을 자동으로 둔다. 자르지 않은 원본(204×192)을 그대로 쓰면 높이 56px, 폭 59.5px로 나와 PPTX와 다르다. 자른 파일을 쓰면 폭이 넘치므로 "정사각형 칸(56×56) 안에 비율을 지켜 맞춘다"로 하는 안.
  - 프롬프트 박스의 아이콘은 지금 높이를 `--promptbox-icon-height`(43px)에 맞추고 폭을 자동으로 둔다. 자른 캐릭터(1.48:1)를 높이 43px로 놓으면 폭이 약 64px이 되어 PPTX(64×43.1)와 맞는다.
- 미결: 이 아이콘이 들어간 칩을 샘플 슬라이드에서 그냥 `icon`으로 쓸지, 강의 전용 요소(`ClaudeChip`)로 만들지. ADR [261007_004] ADR-9의 예는 강의 전용 요소이다.

- **결정(사용자)**
  - **기본(도구의 `Chip`)은 아이콘을 줄 수도, 안 줄 수도 있다.** 지금의 `icon` 선택 속성 그대로이다.
  - **강의 전용 요소로 `ClaudeChip`, `TerminalChip`, `FileChip`을 만든다.** 각각 claude 이미지, 터미널 아이콘, 파일 아이콘을 미리 정해 둔 `Chip` 변형이다(ADR [261007_004] ADR-9). 앞의 질문 "`icon`으로 쓸지 강의 전용 요소로 만들지"는 둘 다로 정해졌다(기본 `Chip`은 `icon` 선택, 변형은 강의 요소).
  - 이 요소들은 샘플 강의의 `elements/`에 둔다고 이해한다. 지금 `sample`에는 `elements/`가 없고(`sample2`에만 있음) 슬라이드가 `@/elements`에서 가져온다. `sample`에 `elements/index.ts`를 만들고 슬라이드가 `../../../elements`에서 가져오게 바꾸는 일이 따라온다(ADR-9의 경로 규칙).
- 같이 정할 것(제안)
  - **아이콘 파일**: claude는 `image4.png`(위아래 여백을 잘라서). 터미널과 파일 아이콘은 지금 직접 그린 svg(`icon-terminal.svg`, `icon-file.svg`)인데, 도형 모음의 실제 아이콘(`image3.png` 64×64 터미널, `image5.png` 512×512 파일)으로 바꾸는 안. 직접 그린 것들은 쓸 곳이 없어지므로 지운다(`icon-spark.svg` 포함). VS Code 아이콘은 요청이 없어서 만들지 않는다.
  - **프롬프트 박스의 claude 아이콘**: `ClaudePromptBox`(프롬프트 박스 변형)로 만들지, 슬라이드에서 `icon`으로 줄지. 요청한 변형은 칩 세 가지뿐이다.
  - 샘플 칩의 아이콘: `/bg`, `/resume`, `ctrl + x`는 `ClaudeChip`, `claude agents`는 `TerminalChip`, `CLAUDE.md`는 `FileChip`.

### 요청 5. "완료" 도장에 네온 효과를 준다 (샘플 강의자료의 마지막 장으로 확인함)
- 요청: "완료" 도장에 네온 효과를 준다. 효과의 값은 **샘플 강의자료의 마지막 장**을 보고 확인한다.
- 확인한 것: `2_Agent_View_기반_병렬_개발_r8.pptx`의 마지막 슬라이드(77장 중 77번)에 "완료" 도장이 둘 있다(같은 도장이 `PPT 도형.pptx`에도 있다).
  - 모양: 둥근 사각형 120×57.1px, **35.09° 회전**, 채움 없음, 선 1.5pt(**3px**, 1px = 0.5pt) `#00B0F0`, 글자 `#00B0F0`. 위치는 x1194.2에 y233.1과 y386.7(위아래로 둘). 글자 크기는 지정되어 있지 않다(기본 크기). 글자는 굵지 않다.
  - **도형의 글로우**: 반경 25400 EMU = 2pt = **4px**, 색은 `accent1`에 채도 175%, 투명도 40%. 이 덱의 `accent1`은 Office 기본 파랑 `#4472C4`이고 채도를 올리면 대략 `#1567F4`이다.
  - **글자의 글로우**: 반경 63500 EMU = 5pt = **10px**, 색 `#00B0F0`, 투명도 40%.
  - 네온은 PowerPoint의 **도형 효과 "네온"과 글자 효과 "네온"(glow)**이다. 도형과 글자가 각각 글로우를 가진다. 지금 샘플의 도장(`sl.1_shapes`)은 같은 모양에서 글로우가 없고 글자가 굵은 40px이다.
- 구현안
  - `Shape`에 `glow={{ radius, color }}`(도형의 글로우)를 더한다. 채움이 없는 도형은 테두리를 따라 번진다.
  - 글자 속성(`TextStyle`)에 `glow`(글자의 글로우)를 더한다. `Text`와 `Shape`의 `textStyle`에서 쓴다.
  - 값은 PPTX의 값 그대로(반경 px, 알파를 포함한 색). CSS로는 도형이 `filter: drop-shadow(0 0 반경 색)`, 글자가 `text-shadow: 0 0 반경 색`이다. PowerPoint의 글로우와 번지는 모양이 같지 않아서 눈으로 비교해 조정한다.
  - PPTX로 내보낼 때는 `a:glow`로 그대로 대응한다(PowerPoint 기본 효과).
  - 도장의 값: 선 `#00B0F0`, 글자 `#00B0F0`, 도형 글로우 4px, 글자 글로우 10px, 회전 35.09°, 120×57.1px.
- 같은 효과를 여러 곳에서 쓸 수 있으므로 **일반 속성**(`glow`)으로 둔다. 도장을 강의 전용 요소로 만들지는 정하지 않았다(ADR-9의 예에는 "도장"이 있다).
- 샘플: `sl.1_shapes`의 "완료" 도장에 적용하고, 도장 글자의 크기와 굵기는 PPTX(기본 크기, 굵지 않음)에 맞출지 지금대로(40px, 굵게) 둘지 정한다.

### 요청 6. chapter마다 슬라이드 페이지를 매긴다 (결정됨)
- 배경: chapter는 실제 파일로 배포하는 단위(ADR [261007_002] ADR-3: chapter 하나 = 단일 HTML 하나)라서, 파일 하나 안에서 1번부터 번호가 이어지게 하려는 것이다.
- 지금의 동작(코드로 확인함)
  - 뷰어 하단의 `n / 전체`는 **강의 전체**를 기준으로 센다(`slidesOfCourse`). 예: `ch.3_master`의 슬라이드가 `16 / 19`로 보인다.
  - 사이드바의 슬라이드 번호는 **section마다 1부터 다시 시작**한다(`Sidebar.tsx`의 `i + 1`).
  - 슬라이드 자체에 페이지 번호를 그리는 기능은 없다(ADR [261007_004] ADR-12: 날짜, 바닥글, 슬라이드 번호 슬롯은 나중에).
- **결정**
  1. **사이드바의 번호를 chapter 안에서 이어서 매긴다.** section이 바뀌어도 번호가 이어진다(section 1이 3장이면 section 2는 4번부터).
  2. **하단의 번호(`n / 전체`)는 chapter 기준이다.** chapter를 바꾸면 1부터 다시 시작하고, 전체(`N`)도 그 chapter의 슬라이드 수이다.
  3. **슬라이드 위에 그리는 페이지 번호는 나중에 한다.** 쪽번호 layout(번호 슬롯)을 만들 때 추가한다. ADR-12의 "슬라이드 번호 슬롯은 나중에"는 그대로이다.
  4. **숨김 슬라이드에는 번호를 매기지 않는다.** 번호는 숨김을 건너뛰고 이어진다(내보낸 파일에서 숨김이 빠져도 번호가 같도록). 숨김 슬라이드는 사이드바에서 번호 없이 "숨김" 표시만 보이고, 하단의 `N`(전체)에도 세지 않는다.
  5. **대제목과 목차 슬라이드도 번호를 매긴다.** 번호를 세고 보이는 것도 같다.
- 이 결정이 바꾸는 것
  - ADR [261008_001] ADR-4: "숨김 슬라이드는 이전/다음과 `n / 전체`에 포함된다"에서 **`n / 전체`(번호)에는 포함하지 않는다**로 바뀐다. 이전/다음으로 숨김 슬라이드를 오가는 것은 그대로 둔다(뷰어에서는 보인다).
  - ADR [261007_003] ADR-4 결과("`n / 전체` 기준이 강의인지 chapter인지 미정")가 chapter로 정해진다.
  - ADR [261007_004] ADR-12는 그대로(번호 슬롯은 나중에).
- **결정(사용자)**: **숨김 슬라이드 위에 있을 때 하단의 번호 칸은 `숨김 / N`으로 보인다**(`N`은 숨김을 뺀 chapter의 슬라이드 수). 요청 1에서 뺀 안내문과 달리 번호 칸을 쓰므로 안내문이 다시 생기는 것은 아니다.

### 요청 7. 하단에 chapter 이동 버튼을 더한다 (결정됨)
- 버튼과 모양(사용자가 정함): 하단에 다음 순서로 둔다.

  `<< 이전 챕터`  `< 이전`  `n / N`  `다음 >`  `다음 챕터 >>`

  기호와 글자를 함께 쓴다(예: "다음 챕터 >>"). 마우스를 올리면 설명을 보인다.
- 동작
  - `< 이전`, `다음 >`은 슬라이드 한 장 이동이다. **chapter 끝에서 멈춘다**(첫 슬라이드의 `< 이전`, 마지막 슬라이드의 `다음 >`은 비활성). 지금은 강의 끝까지 chapter를 넘어 가는데 이 동작이 바뀐다.
  - `<< 이전 챕터`, `다음 챕터 >>`는 이전/다음 chapter의 **첫 슬라이드**로 간다(chapter 콤보박스에서 chapter를 고를 때와 같음). 첫 chapter의 `<<`와 마지막 chapter의 `>>`는 비활성이다.
  - **방향키**: `←`, `→`(그리고 지금처럼 PageUp, PageDown)는 `< 이전`, `다음 >`과 같다. **`Ctrl + ←`, `Ctrl + →`는 이전/다음 chapter**이다(`<<`, `>>`와 같음).
- 구현할 때 확인할 것: 콤보박스(`select`)에 포커스가 있을 때 방향키와 `Ctrl + 방향키`가 슬라이드 이동과 겹치지 않는지, 브라우저의 기본 `Ctrl + 방향키` 동작(입력창의 단어 이동)과 충돌하지 않는지. 슬라이드 화면에는 입력창이 없다.
- 영향: `App.tsx`(이동 로직, 하단 버튼, 키 처리), ADR [261007_003] ADR-4(이전/다음의 기준), README 4번(사용법).

### 요청 8. 대제목과 목차를 section 밖으로 뺀다 (결정됨: B안, head와 tail)
- 요청: chapter의 **대제목과 목차는 section에 속하지 않게** 한다. 대제목과 목차는 chapter 전체의 앞머리이지 어느 수업 주제(section)의 일부가 아니다.
- **결정: B안.** chapter `meta.ts`에 **section의 앞에 오는 슬라이드 `head`와 뒤에 오는 슬라이드 `tail`**을 둔다. 항목의 형식은 section의 `slides`와 같다(문자열 또는 `{ id, hidden }`). 슬라이드 폴더는 chapter 폴더 바로 아래에 둔다.
  ```ts
  // courses/{강의}/ch.1_intro/meta.ts
  export default {
    title: "1장 시작하기",
    head: ["sl.1_title", "sl.2_toc"],                    // section 앞 (대제목, 목차)
    sections: ["sec.1_variable", "sec.2_function"],
    tail: ["sl.9_summary"],                              // section 뒤 (요약 등)
  } satisfies ChapterMeta;
  ```
- 규칙(결정에서 따라오는 것, 구현 전)
  - `head`와 `tail`은 선택이다(없으면 비어 있음).
  - 순서는 `head` → `sections` → `tail`이다. 번호는 이 순서로 이어서 매기고(요청 6) 숨김 슬라이드는 건너뛴다.
  - 사이드바: `head` 슬라이드는 section 제목 없이 맨 위에, `tail`은 맨 아래에 보인다. `SECTION n` 번호는 section만 센다. 목차(`Toc`)가 채우는 항목도 section만이다.
  - 상단 바의 위치 표시: section이 없는 슬라이드는 `chapter / 슬라이드`.
  - 배열과 폴더가 어긋나면 `head`, `tail`도 section과 같은 규칙으로 경고한다(ADR [261008_001] ADR-3).
- 지금의 구조와 영향: 슬라이드는 항상 section 안에 있다(`course → chapter → section → slide`). 용어사전, README, CLAUDE.md, ADR [261007_002] ADR-1, ADR [261008_001] ADR-1(순서는 배열)의 계층 설명이 바뀐다. 코드는 `types.ts`(`ChapterMeta.head`, `tail`), `courses.ts`(`ChapterNode`에 `head`, `tail`, `slidesOfChapter`, 슬라이드 파일을 읽는 glob), `Sidebar.tsx`, `findPath`, 샘플의 `meta.ts`와 폴더이다.
- 구현할 때 주의: chapter 바로 아래의 슬라이드(`courses/{강의}/{chapter}/{slide}/index.tsx`)를 읽는 glob이 `courses/{강의}/masters/{id}/index.tsx`와 경로 모양이 같다. chapter 폴더(`meta.ts`가 있고 강의 `chapters` 배열에 있는 폴더)의 아래만 읽도록 해서 마스터 파일이 슬라이드로 읽히지 않게 한다.
- 샘플의 처리(제안, 확인 필요): `ch.3_master`의 대제목(`sl.1_title`)과 목차(`sl.2_toc`)를 `head`로 옮긴다. 각 section의 첫 장(`sl.1_title`, "변수란?" 등)은 section의 소개 슬라이드라 그대로 둔다. `tail`을 보여 줄 샘플이 필요하면 `ch.3_master`에 요약 슬라이드를 둘 수 있다.
